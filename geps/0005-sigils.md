# GEP-0005: Sigils

## Abstract

Sigils are Elixir's `~name<delimiter>body<delimiter>` literal family. This
proposal adds four to the v0 surface: `~w` (word lists), `~s` (strings with
free delimiter choice), `~r` (compiled regular expressions), and `~python` — a
raw sigil that splices a verbatim Python expression into the generated
code. `~python` is the escape hatch that keeps the compiler small when the
host language can already say something directly. Being an expression, a
`~python` value binds and returns like any other value.

## Motivation

Word lists and regexes are everyday literals whose plain-string spellings
are noisy (`["a", "b", "c"]`, escaped backslashes in patterns). More
importantly, a compile-to-Python language needs a principled escape hatch:
when a Python expression has no Gandora spelling (a comprehension, a
`yield`, an exotic operator), authors should embed that one expression
verbatim rather than wrap it in a Python helper module. Embedded-language bodies with a language tag solve this cleanly, in
Elixir's sigil syntax.

## Scope

The four sigils above, their delimiter set, and their raw/interpolating
split. Custom user-defined sigils, sigil modifiers (`~r/x/i`), typed `extern` handles, file-based embeds,
and additional sigils (`~D` dates, `~U` timestamps) are deferred.

## Terminology

- **Sigil**: a literal `~name` followed by a delimited body.
- **Interpolating sigil**: a lowercase-named sigil whose body supports
  `#{...}` interpolation.
- **Raw sigil**: a sigil whose body is taken verbatim: every
  uppercase-named sigil and the embedded-language sigil `~python`.

## Specification

**GEP-0005-R001:** A sigil is `~` immediately followed by an alphabetic
name and a delimited body. Supported delimiter pairs are `( )`, `[ ]`,
`{ }`, and the symmetric `/ /`, `" "`, `| |`, plus triple-quoted
`""" """`. Bracket delimiters nest; symmetric delimiters do not.

**GEP-0005-R002:** In every sigil body, backslashes pass through verbatim
except that a backslash may escape the closing delimiter (and `\\` spells
a literal backslash before a closing delimiter). Interpolating sigils
additionally support `#{expr}`; raw sigils treat `#{` as text. Lowercase
names interpolate except `~python`, whose body is raw host code.

**GEP-0005-R003:** A letter immediately following the closing delimiter
(an Elixir sigil modifier) MUST produce a diagnostic saying modifiers are
not supported.

**GEP-0005-R004:** `~w(one two three)` evaluates to the list of
whitespace-separated words, `["one", "two", "three"]`. With
interpolation the split happens at runtime on the interpolated string.

**GEP-0005-R005:** `~s(...)` evaluates to a string, identical to a
double-quoted string but with delimiter freedom.

**GEP-0005-R006:** `~r(...)` evaluates to a compiled regular expression:
it compiles to `re.compile(<body>)` with an implicit `import re`. The
body reaches Python's `re` engine byte-for-byte (modulo R002), so Python
regex syntax — not Erlang's — is the contract.

**GEP-0005-R007:** `~python(...)` is a raw sigil whose body MUST be a single
Python expression; the compiler splices it verbatim, wrapped in
parentheses, into the generated code at the sigil's expression position.
The compiler performs no validation of the body beyond non-emptiness;
errors surface from Python. Gandora bindings in scope at the sigil's
position are visible to the body under the GEP-0001-R015 name mapping.

**GEP-0005-R008:** `~python` bodies are opaque to the compiler: macro
hygiene does not rename names inside them, and tooling MUST treat them as
Python, not Gandora. A `~python` body MUST NOT be generated by macro
expansion in v0.

**GEP-0005-R009:** *Repealed by GEP-0009-R001*: every non-built-in name
is now an embedded-language sigil.

## Rationale

The raw/interpolating case split follows Elixir exactly, so knowledge
transfers. Backslash pass-through (rather than full escape processing)
is what makes `~r(\d+)` writable without double escaping; it matches how
Elixir treats sigil bodies.

`~python` deliberately compiles to a parenthesized verbatim splice rather
than an `eval` or a helper call: the output stays readable, has zero
runtime cost, and behaves exactly like the hand-written Python it is.
The host language is a feature, not a failure mode — restricted here to
single expressions so the splice cannot break the surrounding statement
structure. Statement-level embedding (functions, classes) remains the job
of ordinary Python modules plus `pyimport`.

## Backwards Compatibility

Purely additive; `~` was previously an invalid character.

## Security and Determinism

Sigils are literals; compilation remains free of execution. `~python` splices
author-written text into generated output exactly as a hand-written
Python file would contain it — it grants no capability the project's own
Python files lack. Generated output remains deterministic.

## Tooling and AI Usage

Agents should prefer `~w`/`~r` over hand-built equivalents, reach for
`~python` only when a Python expression has no Gandora spelling, and keep
`~python` bodies to one readable expression — anything longer belongs in a
Python module imported with `pyimport`.

## Rejected Alternatives

### Compile `~r` to a Gandora-side regex AST

A portable regex model would decouple the surface from Python, but the
target is Python and its `re` module is the runtime either way;
re-encoding regex syntax buys nothing and breaks copy-paste from Python.

### An `embed python do ... end` block form for statements

Statement-level embedding would duplicate what `pyimport` of an ordinary
Python module already does well, and it invites unstructured code
injection into module scope. The expression-only sigil keeps the escape
hatch small.

### Full Elixir escape processing in sigil bodies

Processing `\n` and friends inside `~r` would force regex authors to
double every backslash, the classic sigil failure; pass-through matches
Elixir's actual behavior and regex expectations.

## Open Questions

None for this revision.

## Conformance

Tests MUST cover: each delimiter pair including nesting and the escaped
closing delimiter; interpolation in `~w`/`~s`/`~r` and its absence in
`~python`; word splitting (literal and runtime); `re.compile` output with
backslashes preserved; `~python` splices in expression position including
inside pipes and calls; the modifier diagnostic (R003); and the unknown
sigil diagnostic (R009).
