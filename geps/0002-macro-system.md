# GEP-0002: The Macro System

## Abstract

Gandora macros are compile-time functions from syntax to syntax, written
with `defmacro`, `quote`, `unquote`, and `unquote_splicing` in Elixir's
spelling. Expansion is hygienic by default, runs in a deterministic sandbox
inside the compiler, and completes before Python code generation. This
follows the macro model of the Osiris project (phase-separated, hygienic,
data-driven) while keeping Elixir's authoring surface.

## Motivation

A macro system lets the standard library and user code grow the language
(control-flow forms, DSLs, boilerplate elimination) without enlarging the
compiler for every feature. Hygiene and phase separation are required so
that expansions are safe to compose and builds stay reproducible.

## Scope

`defmacro` definition and invocation, quoting forms, hygiene rules, the
expansion sandbox, and `gan expand`. Macro export/import across packages
beyond project-local modules is deferred.

## Terminology

- **AST value**: the quoted representation of Gandora syntax that macros
  receive and return.
- **Expansion phase**: the compile-time evaluation of macro bodies.
- **Hygiene**: the property that names introduced by a macro template do not
  capture or collide with names at the call site.

## Specification

**GEP-0002-R001:** `defmacro name(params) do body end` defines a macro.
Macros MUST be defined at module top level. A macro call is expanded at
compile time; its result MUST be an AST value, which re-enters expansion
until no macro calls remain, with a bounded expansion depth.

**GEP-0002-R002:** Macro arguments arrive unevaluated as AST values.
`quote do ... end` builds an AST value; `unquote(expr)` inserts an evaluated
AST value into a quote; `unquote_splicing(list)` splices a list of AST
values into the enclosing sequence. The quoted representation MUST follow
Elixir's shape: a call is `{name, meta, args}` and literals represent
themselves.

**GEP-0002-R003:** Macro bodies MUST be evaluated by a deterministic
compile-time interpreter over the expression subset of Gandora (bindings,
arithmetic and comparison, boolean forms, `if`/`case`/`cond`, list and
tuple and map construction, pattern matching, calls to other
compile-time-available functions and macros, and the quoting forms). Macro
bodies MUST NOT perform I/O, import Python, read the clock or environment,
or observe anything outside their arguments. Identical inputs MUST produce
identical expansions.

**GEP-0002-R004:** Expansion MUST be hygienic by default: a variable bound
inside a `quote` template is renamed to a fresh, expansion-unique name, so
it cannot capture or be captured by call-site bindings. Variables inserted
via `unquote` keep call-site identity. `var!(name)` inside a quote
deliberately escapes hygiene and uses the call-site name.

**GEP-0002-R005:** A compile error raised while expanding a macro MUST
report both the macro call site and the location inside the macro
definition, as an ordered origin chain.

**GEP-0002-R006:** Macros used by a module MUST come from the same module
or from modules named by `require` or `import` (GEP-0001-R006). Macro
resolution MUST NOT depend on file compilation order; the compiler resolves
the project dependency graph first, and macro-dependency cycles are a
compile error.

**GEP-0002-R007:** `defmodule`, `def`, `defp`, `defmacro`, `alias`,
`import`, `require`, and `pyimport` MUST NOT be generated by macro
expansion in v0; macros produce expressions and statements inside bodies.
This restriction MAY be lifted by a future GEP.

**GEP-0002-R008:** `gan expand <file>` MUST print the module after full
macro expansion, rendered in surface syntax, without writing any artifact.

**GEP-0002-R009:** Macros exist only at compile time. A module whose body
declares no runtime code — no functions, no struct, no module attributes,
no `import` re-exports — MUST produce no generated Python file, and a
build MUST remove a previously generated file for it. Running such a
module MUST fail with a diagnostic naming the module.

## Rationale

Interpreting macro bodies inside the compiler (rather than compiling them
to Python and importing them) keeps compilation free of user code execution
and keeps builds deterministic — the same decision Osiris made with its
phase-1 evaluator. Elixir's `{name, meta, args}` quoted shape is kept so
that documentation and intuition transfer directly.

Hygiene-by-default with an explicit `var!` escape matches both Elixir and
Osiris; unhygienic-by-default systems make composed macros fail in ways
users cannot debug.

## Backwards Compatibility

Founding proposal for the macro surface; the quoted AST shape (R002) is the
compatibility contract future tooling depends on.

## Security and Determinism

The expansion sandbox (R003) is the security boundary: macro expansion
cannot exfiltrate data, touch the filesystem, or make builds
non-reproducible. Expansion depth and step limits prevent non-terminating
compiles.

## Tooling and AI Usage

Agents should use `gan expand` to verify macro behavior instead of
reasoning about expansion mentally, and should treat R007's restriction as
the boundary of what a macro may generate in v0.

## Rejected Alternatives

### Compile macros to Python and import them at build time

Faster for heavy macros, but compilation would execute arbitrary user code
and depend on the local Python environment, breaking determinism and the
no-import guarantee of GEP-0001.

### Unhygienic macros with manual gensym

Simpler to implement but pushes correctness onto every macro author;
composition failures surface at user call sites.

## Open Questions

None for v0.

## Conformance

The test suite MUST cover: hygienic renaming, `var!` capture, `unquote`
and `unquote_splicing` in head and tail positions, nested macro calls,
recursion depth failure, the R007 restriction diagnostics, and `gan expand`
output stability.
