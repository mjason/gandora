# GEP-0023: 沙盒

## Abstract

`gan lsc try <file|-> [--no-run]` 以单个 JSON 值的形式回答 AI 智能体在生成 Gandora 代码后提出的问题：*这是正确的吗？如果不是，我可能想要表达什么？* 该管道会编译、检查代码风格、将模块成员与真实符号进行拼写检查，标记常见的跨语言习惯，然后在临时目录中在严格超时限制下执行——捕获标准输出，以及对于裸语句片段，捕获最后一个表达式的值。错误的名称会从编辑距离搜索中获得 Rails 风格的 *did-you-mean* 建议。不会触及项目本身。

## 动机

对于AI代理而言，新语言最大的采用风险是反馈循环：一个看似合理但错误的拼写（`Enum.mpa`、`return`、Python的`def f():`）需要完整的编辑-构建-运行循环才能发现，而运行时的`AttributeError`只指出了症状，而非修复方法。一次快速查询，既能判定错误*又能教导*，将每个错误转化为教训。

## 范围

`gan lsc` 中的一个只读验证查询。持久化沙箱、超出挂钟超时的资源配额以及网络隔离不在范围内：沙箱运行开发者自己的代码，使用项目自己的解释器，就像 `gan run` 那样。

## 规范

**GEP-0023-R001：** `gan lsc try <file|->`（使用 `-` 表示标准输入）接受一个完整模块或裸语句，并输出一个 JSON 对象：`ok`（布尔值）、`stage`（`compile` | `lint` | `run` | `ok`）、`diagnostics`（编译器错误和 GEP-0022 中的 lint 检查，带跨度信息）、`suggestions`（见 R002/R003）、`python`（生成的代码——零运行时承诺的可检查化）、`stdout` 和 `value`（代码片段最后一个表达式的 `repr` 表示）。`--no-run` 在诊断完成后停止执行。执行过程在一个临时的、包含项目解释器的全新目录中进行，并带有硬超时限制；模块的 `main/0` 函数恰好运行一次。

**GEP-0023-R002（拼写纠正建议）：** 拼写错误会从实际候选词中获得编辑距离建议：`Mod.fun(...)` 调用会对照模块的实际符号进行检查（`Enum.mpa` → `Enum.map`），未定义变量 lint 会对照代码片段自身的标识符进行检查（`valeu` → `value`），编译错误位置会对照关键字列表进行检查（`defmodul` → `defmodule`）。建议携带 `"kind": "did_you_mean"`。

**GEP-0023-R003（迁移提示）：** 常见的跨语言习惯会被文本识别，并以 Gandora 的写法给出对应答案——`return`、`while`、`elif`、Python 的 `def ...():`、`lambda`、`None`/`True`/`False`、`import`/`from ... import`、`self.`、`&&`/`||`、增强赋值、f-string、`switch`、`== nil` 以及已废弃的 `$"a.b"`。建议携带 `"kind": "migration"`；它们仅作为参考，绝不会阻止最终判定。

**GEP-0023-R004（实践提示）：** 人工智能很少犯拼写错误——它只是偷懒。已文档化的标准会以 `"kind": "practice"` 建议的形式呈现，而编译器对此保持沉默：一份汇总的注解覆盖率报告（`@spec`/`@doc`/`@moduledoc`，外加缺失 `@example` 的提示）、`@spec` 参数位置中具体的 `list()`/`map()`（“抽象输入，具体输出”）、希望改用 `for` 的 map+filter 管道、希望写成 `&f/1` 的 `fn x -> f(x) end`、希望改用 `Enum.empty?` 的 `count == 0`、希望指定异常类型的裸 `rescue`，以及希望改用 `pyimport`（GEP-0003 修订版 6）的重复 `$module`。

**GEP-0023-R005（信任）：** 字符串、这里文档、符号、注释的内容在文本检查之前会被屏蔽（保留定界符）——散文内容永远不会触发代码模式，一个符合习惯的模块 MUST 产生 `"suggestions": []`。建议按消息内容去重。

**GEP-0023-R007（项目范围）：** `gan lsc review` 对每个项目源文件执行相同的教学检查：整个项目的诊断（如同 `check`）加上每个文件的实践/迁移/成员建议——即沙盒的判断，覆盖整个编译器。

**GEP-0023-R006（人机工程）：** `gan try` 是同一查询的运行级拼写（`gan lsc try` 与之相同）；无目标（或使用 `--help`）时打印技能指南——用法、JSON 契约、建议类型以及智能体循环。退出码在 `ok` 时为 0，否则为 1，因此判定结果可以在脚本中串联使用。

## 原理说明

将沙箱构建到 `lsc` 中保持了单一的 AI 界面：使用 `lsc` 进行检查、阅读文档和查找引用的智能体也同时用它进行学习和验证。文本错误模式被刻意设计得简单——它们的存在是为了教授惯用法，而不是解析 Python——而对真实符号表进行编辑距离搜索，才是使得建议可信而非产生幻觉的原因。

## 向后兼容性

增量式。

## 安全性与确定性

沙箱使用项目解释器执行用户提供的代码——与 `gan run`/`gan test` 相同的信任边界。超时限制的是挂钟时间，而非资源能力；裁决输出是确定性的，除了被执行的程序自身行为外。

## 工具与 AI 使用

Agents SHOULD 在将生成的代码写入项目前，先通过 `gan lsc try` 运行它；将 `did_you_mean` 建议视为要应用的修正；并在无需执行时使用 `--no-run`。循环流程为：生成 → `try` → 应用建议 → `try` → 写入。

## 被拒绝的替代方案

### 长期运行的沙盒服务器

状态会累积并与项目产生偏差；每次查询使用全新的临时目录可保持结果可重现，且实现仅约300行。

### 编译器侧的“您是不是要找？”

编译器保持小巧且确定；模糊搜索属于工具链，其中候选（符号、标识符）已被索引。

## 符合性

BDD 场景套件（给定源 / 尝试时 / 然后判定）MUST 涵盖：干净运行（标准输出、值、单个 `main/0`）、运行崩溃和超时、`--no-run`；每个“你是不是想找”类别；每个迁移模式；每个实践提示；lint 透传；以及 R005 的静默保证（惯用模块、散文、注释、文档文本）。
