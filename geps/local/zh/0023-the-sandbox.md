# GEP-0023: 沙盒

## Abstract

`gan lsc try <file|-> [--no-run]` 以一个 JSON 值回答 AI 代理在生成 Gandora 代码后提出的问题：*这个对吗？如果不对，我可能想表达什么？* 该管道会编译、检查语法、对模块成员进行拼写检查（与真实符号对比）、标记常见的跨语言习惯，然后在临时目录中通过硬超时执行——捕获标准输出，对于裸语句片段则捕获最后一个表达式的值。错误名称会从编辑距离搜索中获得 Rails-style 的 *did-you-mean* 建议。不会触及项目。

## Motivation

一门新语言对AI智能体最大的采用风险在于反馈循环：一个看似合理但错误的拼写（`Enum.mpa`、`return`、Python的`def f()`）需要完整的编辑-构建-运行往返才能发现，而运行时的`AttributeError`指出的是症状，而非修复方法。一次快速查询，既能判定*又能教导*，将每个错误转化为教训。

## 范围

`gan lsc` 中的只读验证查询。持久化沙箱、超出挂钟超时的资源配额以及网络隔离不在范围之内：沙箱使用项目自身的解释器运行开发者自己的代码，与 `gan run` 完全相同。

## 规范

**GEP-0023-R001：** `gan lsc try <文件|->`（使用 `-` 表示标准输入）接受一个完整模块或裸语句，并输出一个 JSON 对象：`ok`（布尔值）、`stage`（`compile` | `lint` | `run` | `ok`）、`diagnostics`（编译器错误和 GEP-0022 的 lint 检查结果，带跨度信息）、`suggestions`（参见 R002/R003）、`python`（生成的代码——零运行时承诺变得可检查）、`stdout` 和 `value`（代码片段最后一个表达式的 `repr`）。`--no-run` 在诊断后停止执行。执行发生在项目解释器所在的新临时目录中，并设有硬超时；模块的 `main/0` 恰好运行一次。

**GEP-0023-R002（你是不是想找）：** 拼写错误会从真实候选词中获得编辑距离建议：`Mod.fun(...)` 调用会对照模块的实际符号进行检查（`Enum.mpa` → `Enum.map`），未定义变量 lint 会对照代码片段自身的标识符（`valeu` → `value`），编译错误位置会对照关键字列表（`defmodul` → `defmodule`）。建议携带 `"kind": "did_you_mean"`。

**GEP-0023-R003（迁移提示）：** 常见的跨语言习惯会被文本识别，并以 Gandora 的拼写方式给出回答——`return`、`while`、`elif`、Python 的 `def ...():`、`lambda`、`None`/`True`/`False`、`import`/`from ... import`、`self.`、`&&`/`||`、增量赋值、f-string、`switch`、`== nil` 以及已废弃的 `$"a.b"`。建议携带 `"kind": "migration"`；它们仅供参考，绝不会阻止判定结果。

**GEP-0023-R004（实践提示）：** AI 很少拼写错误——它只是懒惰。文档化的标准会以 `"kind": "practice"` 的建议形式呈现，在编译器保持静默的地方给出：一份汇总的注解覆盖率报告（`@spec`/`@doc`/`@moduledoc`，加上缺失 `@example` 的备注）、`@spec` 参数位置中具体的 `list()`/`map()`（“抽象入，具体出”）、想要改用 `for` 的 map+filter 管道、想要改用 `&f/1` 的 `fn x -> f(x) end`、想要改用 `Enum.empty?` 的 `count == 0`、想要指定具体异常类型的裸 `rescue`，以及重复的 `$module` 想要改用 `pyimport`（GEP-0003 修订版 6）。

**GEP-0023-R005（信任）：** 字符串、长字符串（heredoc）、符号（sigil）和注释的内容在文本检查之前会被屏蔽（保留定界符）——普通文本绝不会触发代码模式，一个符合惯例的模块 MUST 产生 `"suggestions": []`。建议按消息内容去重。

**GEP-0023-R007（项目范围）：** `gan lsc review` 对每个项目源文件执行相同的教学检查：全项目诊断（类似 `check`）加上每个文件的实践/迁移/成员建议——即沙箱的判断，覆盖整个编译器。

**GEP-0023-R006（人机工程学）：** `gan try` 是同一查询的运行层面拼写（与 `gan lsc try` 相同）；若无目标（或 `--help`）则打印技能指南——用法、JSON 契约、建议种类以及代理循环。退出码为 0 表示 `ok`，否则为 1，因此判定结果可在脚本中串联。

## 理由

将沙箱直接构建到 `lsc` 中，可以保持单一 AI 表面：使用 `lsc` 进行检查、阅读文档和查找引用的代理，同时也通过 `lsc` 进行学习和验证。文本错误模式被刻意设计得简单——它们的存在是为了教授惯用法，而非解析 Python——而基于真实符号表的编辑距离搜索，正是使建议可靠而非幻觉的关键。

## 向后兼容性

新增性。

## 安全性与确定性

沙箱使用项目解释器执行用户提供的代码——与`gan run`/`gan test`相同的信任边界。超时限制的是挂钟时间，而非能力；裁决输出是确定性的，除了所执行程序自身的行为。

## Tooling and AI Usage

Agents SHOULD 将生成的代码通过 `gan lsc try` 路由，然后再写入项目；将 `did_you_mean` 建议视为需要应用的修正，并在无需执行时使用 `--no-run`。循环为：生成 → `try` → 应用建议 → `try` → 写入。

## 被否决的替代方案

### 长期运行的沙箱服务器

状态会积累并与项目偏离；每次查询使用新的临时目录可保持裁决可重现，且实现代码约300行。

### 编译器侧的“你是不是想找”

编译器保持小巧且确定；模糊搜索属于工具链，其中候选对象（符号、标识符）已被索引。

## Conformance

BDD 场景套件（给定源码 / 尝试运行 / 然后判定）MUST 涵盖：干净运行（标准输出、返回值、单个 `main/0`）、运行崩溃与超时、`--no-run`；每个“您是否想表达”类别；每个迁移模式；每个实践提示；lint 直通；以及 R005 的静默保证（惯用模块、散文、注释、文档文本）。
