# GEP-0007: 文档

## 摘要

文档有三个通道，每个通道对应一个属性族，且互不重叠。`@doc`/`@moduledoc` 遵循 Elixir 的约定：Markdown 字符串是文本，关键字列表是元数据（`since:`、`deprecated:` 等），`false` 表示隐藏，重复的行会累积——编译器原样存储文本，并且从不解析其内部内容。`@example` 是专门用于示例的通道：可重复的块，其 `gan>` 行会被编译为原生 Python doctest，附加到生成的文档字符串，由 `gan test` 运行，并在每个语言环境中渲染。`@doc_trans`/`@moduledoc_trans` 添加仅正文的翻译。每个示例只保留一份副本；不存在任何文本提取启发式方法。

## 动机

早期修订尝试将示例保留在文档文本中（Elixir 风格），同时对该文本进行本地化，这迫使编译器解析散文——先是使用区域关键词，然后是标题约定，再是结构提取和包含指令。评审拒绝将解析散文作为一种范式：文档文本应当是不透明的数据。为示例赋予它们自己的属性可消除所有启发式规则：文档文本永不被检查，译文是纯散文，而示例通道是编译器唯一理解的东西。

## 范围

三个通道，即 docstring 组装、doctest 编译以及 `gan doc` / `gan test` 命令。HTML 渲染、`@spec`/`@typedoc` 和文档覆盖率工具推迟实现。

## 术语

- **文档单元**：一个模块或函数的文档：默认文本、翻译、元数据、隐藏标志、示例块。
- **文档测试行**：内容以 `gan> ` 开头的行，包含一个 Gandora 表达式；其后的非空行是其预期输出。
- **示例块**：传递给某个 `@example` 属性的字符串。

## 规范

### @doc — 文本、元数据、隐藏（Elixir 风格）

**GEP-0007-R001:** `@doc` 和 `@moduledoc` 在每条属性行中接受：一个 Markdown 字符串（文本）、一个关键字列表（元数据）或 `false`（隐藏）。一个定义之前的多个行按任意顺序累积为一个文档单元。第二个文本字符串或重复的元数据键是编译错误。文本是不透明的：编译器原样存储文本，MUST NOT 解析、重排或转换其内容。

**GEP-0007-R002:** 元数据值 MUST 是字面量（字符串、布尔值、整数、浮点数、原子）。`since` 和 `deprecated` 键是众所周知的，并且还会在生成的文档字符串中作为尾随的 `Since: <v>` / `Deprecated: <v>` 行出现；除此之外，所有元数据仅面向工具。

**GEP-0007-R003:** `@doc false` 抑制文档字符串并隐藏定义；`gan doc` MUST 说明目标是隐藏的，而不是什么都不打印。

### @example — 编译器理解的唯一通道

**GEP-0007-R004:** `@example "..."` 将一个示例块附加到下一个定义；该属性 MAY 重复，并且 MAY 与 `@doc` 一起使用或单独使用。块保持源代码顺序。在块内部，doctest 行会被编译（R008）；所有其他行原样通过，因此一个块可以携带自己的标题和说明文字。

**GEP-0007-R005:** 生成的文档字符串按以下方式组装：原样的文档文本，然后是每个已编译的示例块，然后是众所周知的元数据尾部（R002），各部分之间用一个空行分隔。`@doc`/`@moduledoc` 文本中的 doctest 行不会被编译或测试——示例属于 `@example`，并且当文档文本包含 `gan> ` 行时，`gan check` MUST 发出警告。

### 翻译 — 仅限散文

**GEP-0007-R006:** `@doc_trans` 和 `@moduledoc_trans` 携带一个或多个 `<locale>: "markdown"` 对；区域设置键拼写 BCP 47 标签时，用 `_` 代替 `-`（`zh_CN` ≡ `zh-CN`）。该属性 MAY 重复；重复的区域设置是编译错误。翻译是从源代码（或包附带的源代码）读取的工具元数据，MUST NOT 出现在生成的代码中。

**GEP-0007-R007:** 翻译中的 doctest 行是编译错误，它会指示作者使用 `@example`。因此，翻译永远不能携带示例的第二份未测试副本。

### 渲染与测试

**GEP-0007-R008:** Doctest 编译：`gan> ` 之后的表达式被编译为 Python 并输出为 `>>> <compiled>`，保留缩进；其期望行原样通过。期望输出由 Python 的 doctest 运行器进行比较，因此是结果的 `repr` — 即 `inspect/1` 所打印的内容。Doctest 表达式 MUST 是单行，并且在 v0 中 MUST NOT 使用宏；编译失败是携带定义位置的编译错误。

**GEP-0007-R009:** `gan doc <Module>[.<function>] [--locale <tag>]` 渲染：首先是元数据（`[deprecated]` 突出显示），然后是按 RFC 4647 查找选择的区域设置的文本（精确匹配、缩短前缀，然后默认），然后是每个示例块及其原样的 `gan>` 提示。它从项目源代码和已安装的包标记（GEP-0006-R006）解析模块，静态读取，并且从不导入 Python。

**GEP-0007-R010:** `gan test` 将项目编译到构建缓存中，并通过 Python 的标准 doctest 运行器运行每个生成的非仅宏模块，使用 GEP-0001-R021 解释器、`-P` 以及 `PYTHONPATH` 上的缓存，按点分模块名称导入。它报告每个模块的结果，并且仅在全部通过时以 0 退出。生成的 doctest 是标准的：`python -m doctest` 和 pytest 的 `--doctest-modules` MUST 在没有 `gan` 的情况下也能在生成的文件上工作。

**GEP-0007-R011:** 默认文档通道 — `@doc`、`@moduledoc`、`@param` — 使用英文编写；其中包含 CJK 码点的文本是编译错误，在检查阶段被捕获，并提示使用 `_trans` 拼写。本地化散文有自己的通道（`@doc_trans`、`@moduledoc_trans`、`@param_trans`、R001A/GEP-0018-R003），并且保持不动，`@example` 正文和注释也是如此。原因是检索（GEP-0031）：轻量级的 `@doc` 句子是代码映射排序的语义键 — 一个在单一通道中混合语言的语料库不会在任何一个语言中排名，而每个通道一种语言可以让智能体按含义搜索，并让每个区域设置在旁边保留自己的全权重散文。

## 理由

三个职责分离的通道使得所有早期失败模式在结构上变得不可能：文本是不透明的（没有解析范式），示例恰好只存在于为它们构建的通道中，翻译则是纯数据。代价是偏离 Elixir 一处——示例从文档文本移入 `@example`——评审认为这比解析散文成本更低；R005 警告会捕获遗留在文档文本中的 Elixir 习惯性 `gan>` 行。

将 `gan>` 编译为原生 Python doctest 保持了无运行时属性，并复用了成熟的运行器；期望输出即 repr 的形式对 GEP-0001-R009 的数据映射是忠实的。

## 向后兼容性

修订版5取代了修订版1至4：`@doc_meta`/`@moduledoc_meta` 和 `<!-- examples -->` 指令被移除；文档文本中的 doctest 不再被编译（改为警告）；`@example` 是唯一的 doctest 载体。`@doc` 字符串/关键字/false 形式及 `@doc_trans` 保持不变。

## 安全性与确定性

Doctest 编译是普通的表达式编译；编译期间不执行任何操作。`gan test` 执行用户自己生成的代码，与 `gan run` 完全相同。

## 工具与 AI 使用

Agent 应编写 Markdown 格式的 `@doc` 正文，将每个可运行的示例放入 `@example` 中，使用 `@doc since:`/`deprecated:` 附加元数据，保持翻译仅包含正文，并在编辑后运行 `gan test`。

## 已拒绝的备选方案

### 在文档文本中内联 Doctests（修订版 1–4）

Elixir 自身的布局，但面对本地化文本时，它要么迫使翻译中出现重复示例（腐化），要么需要编译器解析散文（抽取启发式、包含指令）。审查拒绝了将散文解析作为一种范式；专用通道完全不需要它。

### 在 @doc 内使用区域设置关键字

将主要文本埋在 `default:` 标签后面，并使每个翻译后的标题都变成一个冗长的属性。

### 在文档字符串中嵌入所有区域设置

用大多数消费者无法阅读的文本使每个构件膨胀；工具改为从源代码读取区域设置。

## 未决问题

本修订版本无未决问题。

## 一致性

测试 MUST 覆盖：以任意顺序出现的字符串/关键字/`false` 形式的 `@doc` 行累积（含重复文本和重复键诊断）；元数据尾部；文档字符串组装顺序（文本、示例、尾部）；带与不带 `@doc` 的 `@example`；对文档文本中的 `gan>` 发出 R005 警告；R007 翻译诊断；保留缩进的 doctest 编译；`gan doc --locale` 中的 locale 回退与示例渲染；由 `gan test` 检测到的失败 doctest；以及由 `python -m doctest` 直接运行的生成模块。
