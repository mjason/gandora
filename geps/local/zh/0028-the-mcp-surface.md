# GEP-0028: MCP 接口面

## 摘要

`gan-mcp` 是一个使用 Gandora 编写的 Model Context Protocol 服务器，它将工具链暴露给任何 MCP 客户端。它承载模型所需的答案——文档、上下文包、裁决——以及一个先前任何表面都无法给出的答案：**一个已被编译、判定并真正运行的完整模块**。本 GEP 固定了整个表层旨在强制执行的规则：未被运行过的东西一律不予返回。

## 动机

GEP-0025 将修正变成一次调用，GEP-0026 将发现变成一次调用。两者都改进了模型*知道*什么；但都没改变模型*交付*什么。模型仍然写出代码片段、读回它、觉得它似乎合理、然后交给用户——而“看似合理”并不是裁决。观察到的失败不在于对语法的无知，而在于没有证据的自信：代码读起来正确、引用了一个不存在的函数，却仍然到达了用户手中。

Gandora 处于异常有利的位置来弥合这一缺口。`@example` 不是装饰：它编译成本地 Python doctest，由 `gan test` 执行（GEP-0007）。因此，示例本身就是一种断言；带有示例的模块是一个可自我验证的工件。生成示例和测试它是同一个行为；跳过后半部分的界面是有意为之。

服务器应放在这里而非客户端中的第二个原因：MCP 从函数签名推导工具的 `inputSchema`，而 Gandora 从 `@spec` 推导签名，并从 `@doc`/`@param` 派生描述。Advisor 已经在强制执行的注解纪律正是该协议的元数据。契约只书写一次。

## 范围

涵盖：stdio 服务器、其工具表面、验证流水线、将需求转化为已验证模块的 composer，以及将其接入读取需求的代理的项目级配置。范围之外：HTTP 传输、MCP 采样，以及简报之外的提示与资源。

## 术语

**沙箱项目** — 一个临时项目，包含一个模块，每次请求时构建并丢弃。

**原子示例** — 对一种语言能力的已验证示例，取自测试套件已在运行的源。

**组合器** — 从需求到模块的、由模型支持的路径。

## 规范

**GEP-0028-R001（服务器）：** `gan-mcp` 通过 stdio 使用 MCP 协议进行通信，且其本身就是一个 Gandora 程序。`GAN_MCP_ROOT` 选择其查询所针对的项目，默认为工作目录。

**GEP-0028-R002（无不经运行）：** 每个包含代码的答案 MUST 携带产生它的判定：诊断信息、实践建议，以及执行该模块 doctests 的结果。模块未达到 `ok: true` 的答案 MUST 作为携带这些发现的失败结果返回。以散文形式返回未经验证的代码——无论看起来多么合理——都是此表面的缺陷，而非其降级模式。

**GEP-0028-R003（流水线）：** 验证将模块写入沙盒项目中该模块自身 `defmodule` 所要求的位置（GEP-0001-R013），其判定取自 `gan lsc check`（GEP-0025-R009）而非任何私有重新实现，在硬超时下执行编译产物的 doctests，并在之后移除沙盒。用户的项目永不被写入。

**GEP-0028-R004（schema 不写两次）：** 工具输入派生自 `@spec`，描述派生自 `@doc` 和 `@param`。工具函数 MUST NOT 接受默认参数（默认参数会抹除生成的签名），且 MUST 携带足够精确、足以作为公共契约的 spec。

**GEP-0028-R005（零成本工具）：** `gan_doc`、`gan_pack`、`gan_check` 和 `gan_briefing` 转发已经存在的表面（GEP-0015、GEP-0025、GEP-0026），且 MUST NOT 咨询模型。无法被创造者，MUST NOT 被创造。

**GEP-0028-R006（编排者解释并演示）：** `gan_example` 接受一个要演示的特性、语法或能力，并返回两样东西：一段散文式**解释**，以及一个**完整模块**——包含 `defmodule` 与 `@moduledoc`，且每个公共函数都具有 `@doc`、`@param`、`@spec` 和至少一个 `@example` doctest——并且该模块已通过 R002。它 MUST NOT 返回裸片段：片段无法编译、无法进行 doctest、也无法成为 atom，因此根本无法被验证。**答案中的每一行代码 MUST 存在于已验证的模块中。** 解释中的代码是伪装成已验证主张的未验证主张，因此该表面会将其剥离。

**GEP-0028-R007（生成前先接地）：** 编排者的提示词 MUST 携带上下文包和与该需求相关的 atom。模型被要求基于所提供的事实进行编排，绝不凭记忆回想这门语言。

**GEP-0028-R008（判定驱动投入）：** 编排者在首次尝试时以禁用推理的方式运行。提升下一次尝试投入的是失败的判定——而非对难度的猜测。轮次是有限的；当最后一轮失败时，该表面返回发现和最接近的已验证 atom，绝不返回最后一份草稿。

**GEP-0028-R009（atom 是挣得的）：** 一个 atom MUST 来自测试套件所运行的来源——std 或 tour 中的 `@example`，或已通过 R002 的编排模块。一次通过的编排 MAY 被记录为 atom；记录它并不免除其在被提供时接受重新验证。

**GEP-0028-R010（执行模型编写的代码）：** 沙盒运行服务器未编写的代码。它 MUST 在临时目录中、在超时限制下执行，MUST NOT 可被用户的项目访问，且其失败 MUST 以判定的形式呈现，而非作为跨越协议边界的异常。

**GEP-0028-R011（凭据）：** 模型配置来自环境（`GAN_API_KEY`、`GAN_MODEL`，以及可选的 `GAN_BASE_URL`，默认指向供应商端点）。凭据 MUST NOT 被记入日志、回显到判定中，或写入沙盒。

**GEP-0028-R012（项目拥有接线）：** `gan init` MUST 写入每个 agent 各自读取的项目级 MCP 配置，采用该 agent 文档记载的形态和位置——Claude Code 使用 `.mcp.json`，Codex 使用 `.codex/config.toml`，opencode 使用 `opencode.json`——且 MUST NOT 覆盖已存在的文件。每个此类文件都声明同一条无路径命令 `uv run gan mcp`：没有 `cwd`、没有绝对路径、没有环境。`uv run` 从客户端启动的任意位置解析项目环境，`gan` 在该项目的 `.venv/bin` 中找到 `gan-mcp`（GEP-0013-R003），服务器则通过向上查找最近的 `gandora.jsonc` 来发现项目。因此，`gandora-mcp` 是每个由脚手架生成的项目的开发依赖。这些文件本就应当被提交：一旦签入，接线对每个克隆该项目的人都有效，而它们所产生的判定是项目自己的——在项目自身环境中作出评判，而非由恰好安装在系统中的任何工具链来评判。

## 理由

这一接口拒绝了大多数代码生成工具所接受的那种分割——一条从模型获得答案的快速路径，和一条进行检查的慢速路径。在这里，检查*就是*答案：带有通过 doctest 的 `clean: true` 判定，是此服务端与一个读过手册的模型之间唯一的区别。将这一点设为不可妥协（R002），才使代理能够把结果直接交给用户。

R006 选择模块而不是片段，因为模块是工具链能够判断的最小单元。片段读起来更短，却无法验证；多出的行就是证据。将答案一分为二，正是该语言已经对其自身文档采取的那套原则：`@doc` 是说明文字，`@example` 会被执行，且没有任何内容能同时是两者。

驱动组合器的提示词本身是用该语言的提示词语法书写的——即带有 `<%= %>` 拼接的 `~p"""`（GEP-0009-R006）——并且它不携带任何手写模块模板。答案的形态由测试套件编译并运行的语料库模块展示，因此流水线中无人验证过的那段代码并不存在。

R008 颠倒了通常的推理预算问题。当循环中有一个依据真实答案（ground truth）进行校验的验证器时，携带真实诊断的一次迭代，比针对同一猜测的更深入思考更有教益——因此努力跟随失败，而不是预判失败。

## 安全性与确定性

该沙箱执行生成的代码，这与 `gan run` 已经代表用户跨越的信任边界相同，但范围被收窄：临时目录、硬超时、无网络要求、事后删除。对于未变的工具链，已验证的答案是可重现的——判定结果和 doctest 输出是关于产物的客观事实，而非关于起草该产物的模型的事实。

## 工具与 AI 使用

一个 MCP 客户端 SHOULD 在每次会话中调用一次 `gan_briefing`，为获取含义调用 `gan_doc` 或 `gan_pack`，并对其打算交付的每个模块调用 `gan_verify`——包括它自己编写的模块。`gan_example` 适用于需求明确但形态不明确的情况。

## 一致性

测试 MUST 覆盖：一个正确的模块在 doctest 运行并通过后达到 `ok`/`clean`；一个调用不存在的标准库函数的模块失败并产生工件诊断；一个期望 doctest 输出错误但编译干净的模块，其 doctest 失败；从模块名到沙箱路径的推导，包括点分名称；从 `@spec` 推导出的工具模式；每个语料库模块都能经受住它所教导的同一判定；以及组合器要么返回一个解释和一个通过 R002 的模块，要么返回一个带有发现的失败——绝不返回未经验证的草稿。
