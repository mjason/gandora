# GEP-0028：MCP 表面

## 摘要

`gan-mcp` 是一个用 Gandora 编写的 Model Context Protocol 服务器，它将工具链暴露给任何 MCP 客户端。它承载着模型所需的答案——文档、上下文包、判定结果——以及一个以往任何界面都无法给出的答案：**一个完整的、经编译、判定并真正运行过的模块**。本 GEP 确立了整个界面存在所要执行的规则：未经运行的内容一律不予返回。

## 动机

GEP-0025 将纠正变成一次调用，GEP-0026 将发现变成一次调用。
两者都改善了模型所*知道*的内容，却都没有改变模型所*交付*的内容。模型仍然会写出一段代码，自己读一遍，觉得它貌似合理，然后交出去——而“貌似合理”并不是定论。观察到的失败不是对语法的无知，而是没有证据的自信：代码读起来正确，引用了一个不存在的函数，却仍然送到了用户手中。

Gandora 拥有非比寻常的优势来弥补这一点。`@example` 不是装饰：它会被编译成 Python 原生的 doctest，由 `gan test` 执行（GEP-0007）。因此，示例本身就是一种断言；带有一个示例的模块就是一个可自我验证的产物。生成示例与测试示例是同一个行为；一个跳过后半部分的界面，就是在选择这样做。

第二个理由是，该服务端应放在这里而不是客户端：MCP 会根据函数签名推导工具的 `inputSchema`，而 Gandora 会根据 `@spec` 推导签名，并从 `@doc`/`@param` 获取描述。Advisor 已经在执行的注解规范，正是该协议的元数据。这份契约只写一次。

## 范围

涵盖内容：stdio 服务器、其工具表面、验证流水线、将需求转化为已验证模块的组合器，以及将该组合器接入读取需求的代理的项目级配置。不在范围内：HTTP 传输、MCP 采样，以及简报之外的提示词和资源。

## 术语

**沙箱项目** — 一个一次性项目，包含一个模块，按请求构建并丢弃。

**原子** — 一种语言能力的已验证示例，取自测试套件已运行的来源。

**编排器** — 从需求到模块的模型驱动路径。

## 规格说明

**GEP-0028-R001（服务器）：** `gan-mcp` 通过 stdio 进行 MCP 通信，并且它本身就是一个 Gandora 程序。`GAN_MCP_ROOT` 选择其查询所应答的项目，默认为工作目录。

**GEP-0028-R002（无未运行之物）：** 每个包含代码的答案 MUST 携带产生该答案的裁决：诊断信息、实践建议，以及执行模块 doctest 的结果。模块未达到 `ok: true` 的答案 MUST 作为携带这些发现的失败结果返回。将未经验证的代码以文字形式返回——无论多么貌似合理——都是此接口的缺陷，而非其降级模式。

**GEP-0028-R003（流水线）：** 验证将模块写入沙盒项目，路径由其自身的 `defmodule` 决定（GEP-0001-R013）；其裁决取自 `gan lsc check`（GEP-0025-R009），而非任何私有的重新实现；在硬超时下执行编译产物的 doctest；之后移除沙盒。用户的项目永远不会被写入。

**GEP-0028-R004（模式不写两遍）：** 工具输入从 `@spec` 派生，描述来自 `@doc` 和 `@param`。工具函数 MUST NOT 使用默认参数——这会抹除生成的签名——并且 MUST 携带足够精确的 spec，以作为公共契约。

**GEP-0028-R005（零成本工具）：** `gan_doc`、`gan_pack`、`gan_check` 和 `gan_briefing` 转发已存在的接口（GEP-0015、GEP-0025、GEP-0026），并且 MUST NOT 咨询模型。无法被发明之物 MUST NOT 被发明。

**GEP-0028-R006（创作者解释并演示）：** `gan_example` 接受一个要演示的特性、语法或能力，并返回两样东西：一段**文字解释**，以及一个**完整模块**——包含 `defmodule` 与 `@moduledoc`，并且每个公共函数都有 `@doc`、`@param`、`@spec` 以及至少一个 `@example` doctest——且该模块已通过 R002。它 MUST NOT 返回裸露的代码片段：片段无法编译、无法进行 doctest、也无法成为原子，因此根本无法被验证。**答案中的每一行代码 MUST 存在于已验证的模块中。** 解释中的代码将是伪装成已验证主张的未验证主张，因此接口会将其剔除。

**GEP-0028-R007（生成前先锚定）：** 创作者的提示 MUST 携带上下文包以及与需求相关的原子。模型被要求从提供的事实中进行创作，绝不去回忆该语言。

**GEP-0028-R008（裁决驱动投入）：** 创作者在首次尝试时禁用推理运行。失败的裁决——而非对难度的猜测——才会提高下一次尝试的投入。轮次有上限；当最后一轮失败时，接口返回发现和最近的已验证原子，绝不返回最后的草稿。

**GEP-0028-R009（原子须赢得）：** 原子 MUST 来自测试套件运行的来源——标准库或导览中的 `@example`，或通过 R002 的已创作模块。验证通过的创作 MAY 被记录为原子；记录它并不免除其在被提供时重新验证的义务。

**GEP-0028-R010（执行模型编写的代码）：** 沙盒运行并非服务器编写的代码。它 MUST 在临时目录中、在超时限制下执行，MUST NOT 可被用户的项目访问，并且其失败 MUST 作为裁决呈现，而非作为跨越协议边界的异常。

**GEP-0028-R011（凭证）：** 模型配置来自环境变量（`GAN_API_KEY`、`GAN_MODEL`，以及可选的 `GAN_BASE_URL`，默认指向厂商端点）。凭证 MUST NOT 被记录日志、回显到裁决中，或写入沙盒。

**GEP-0028-R012（项目拥有接线）：** `gan init` MUST 写入项目级 MCP 配置，每个代理按各自的文档化格式和位置自行读取——Claude Code 为 `.mcp.json`，Codex 为 `.codex/config.toml`，opencode 为 `opencode.json`——并且 MUST NOT 覆盖已存在的配置。每个此类文件声明同一条无路径命令 `uv run gan mcp`：没有 `cwd`，没有绝对路径，没有环境变量。`uv run` 从客户端启动的任何位置解析项目环境，`gan` 在该项目的 `.venv/bin` 中找到 `gan-mcp`（GEP-0013-R003），服务器通过向上遍历查找到最近的 `gandora.jsonc` 来发现项目。因此 `gandora-mcp` 是每个脚手架项目的开发依赖。这些文件本应被提交：一旦签入，接线对每个克隆者都有效，并且它们产生的裁决属于项目自身——在项目自己的环境中评判，而非由系统范围内恰好安装的任何工具链来评判。

**GEP-0028-R012A（代理指令属于代理，修订版 5）：** `gan init` 永远不会向 `AGENTS.md` 或 `CLAUDE.md` 写入任何内容。这些文件承载着每个代理自身的约定、结构和语气；工具向其中追加通用章节是污染，而非接线——修订版 4 恰恰规定了这一点，并在同一天面对一个真实项目时被撤回。R012 的配置文件在性质上不同：它们是机器读取的、单一形态的，并且由我们来定义。作为替代，自我设置路径是服务器的 `instructions`：它们告诉一个在其自身指令文件中缺少 Gandora 覆盖的连接代理，自行按照该文件的约定添加一个简短章节——循环、编辑前检索、`gan_verify` 作为唯一证明。每个 AI 通过其正常的编辑流程配置自身，用户在一旁观看；MCP 服务器保持其永不写入项目的属性。

## 原理

该界面拒绝了大多数代码生成工具所接受的分割——一条从模型作答的快速路径和一条进行校验的慢速路径。在这里，校验*就是*答案：`clean: true`且文档测试通过的判定，是这台服务器与一个读过手册的模型之间唯一的区别。使这一点不可协商（R002），正是让智能体能够直接将结果交给用户的原因。

R006选择模块而非片段，因为模块是工具链能够判断的最小单位。片段读起来更短，却无法验证；多出来的那些行就是证据。将答案一分为二，正是该语言已经应用于自身文档的同一纪律：`@doc`是散文，`@example`被执行，没有什么是两者兼得的。

驱动编写器的提示本身就是用该语言的提示语法编写的——`~p"""`与`<%= %>`拼接（GEP-0009-R006）——并且它不携带任何手写的模块模板。答案的形状由测试套件编译并运行的语料库模块展示出来，因此，流水线中不再存在任何未经验证的代码。

R008反转了通常的推理预算问题。当循环中存在一个真值验证器时，一次携带真实诊断的迭代，比在同一个猜测上进行更深入的思考更有教益——因此，努力在失败之后投入，而非预料失败。

## 安全性与确定性

沙箱执行生成的代码，这与 `gan run` 已经代表用户跨越的信任边界相同，但范围更窄：临时目录、硬超时、无网络要求、之后移除。对于未更改的工具链，验证过的答案是可复现的——判定结果与 doctest 输出是关于工件的事实，而非关于生成该工件的模型。

## 工具与 AI 使用

MCP 客户端 SHOULD 在每次会话中调用一次 `gan_briefing`，调用 `gan_doc` 或 `gan_pack` 以获取含义，并对其打算移交的每个模块调用 `gan_verify`——包括其自行编写的模块。当需求明确但形态不明时，使用 `gan_example`。

## 一致性

测试 MUST 覆盖：一个正确的模块在 doctests 运行并通过后达到 `ok`/`clean`；一个调用不存在的标准库函数的模块失败并产生工件诊断信息；一个模块的 doctest 预期输出错误，编译干净却在 doctests 中失败；模块名到沙箱路径的推导（包括带点号的名称）；从 `@spec` 推导出的工具模式；每个语料库模块都能得到它所教导的相同判定；以及组合器要么返回一个说明和一个通过 R002 的模块，要么返回带有发现的失败——绝不返回未经验证的草稿。

  当 `AGENTS.md` 不存在时创建它，存在时追加由标记分隔的 Gandora
  区块，并向已有的 `CLAUDE.md` 添加一个 `@AGENTS.md` 导入。该区块
  是一个指针，而非规则手册的副本；MCP 服务器仍然不向项目写入任何
  内容。已被修订版 5 撤回。

- 修订版 3，2026-08-08：一次写入契约现已完全接通。工具就是实现
  它的函数上的一个单纯的 `@tool true` 标记（`defattr`/`@on_definition`，
  GEP-0008 rev 2）——钩子从定义自身的名称和元数推导出表条目——注册
  将整个注解表面带入协议：`@doc` 文本就是工具描述（以前手工维护的
  简介会覆盖它），每个 `@param` 文本都会被注入到其 `inputSchema`
  属性中，这些文本是从我们自己的代码生成器生成的 `## Parameters`
  docstring 区块解析出来的（GEP-0018）——这是契约而非猜测。该标记
  自身不携带任何文本：在同一定义上再开一条描述通道，恰恰是本 GEP
  旨在禁止的重复。工具的任何信息都不会被写入两次。

- 修订版 2，2026-08-07：已接受。`gandora-mcp` 作为第六个已发布的
  包加入发布链，R012 使 `gan init` 为 Claude Code、Codex 和 opencode
  写入项目级 MCP 配置——一条无需路径的命令，已签入，对每个克隆
  项目的人都有效。
- 修订版 1，2026-08-06：初始版本。
