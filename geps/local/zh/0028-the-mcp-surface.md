## 摘要

`gan-mcp` 是一个 Model Context Protocol 服务器，使用 Gandora 编写，将工具链暴露给任何 MCP 客户端。它承载着模型所需的答案——文档、上下文包、判定——以及一个任何先前界面都无法给出的答案：**一个已经过编译、判定并真正运行的完整模块**。本 GEP 确立了整个界面所要强制执行的规则：任何未经运行的内容都不会被返回。

## Motivation

GEP-0025 将修正变为一次调用，GEP-0026 将发现变为一次调用。两者都改善了模型所*知道*的内容；但都没有改变模型所*交付*的内容。模型仍然会写一段代码、回读一遍、觉得它貌似合理、然后交出去——而“貌似合理”并非定论。观察到的失败并非对语法的无知，而是没有证据的自信：代码读起来没有问题，调用了一个并不存在的函数，却仍然到达了用户手中。

Gandora 处于一个异常有利的位置来弥合这一差距。`@example` 并非装饰：它编译为一个原生 Python doctest，由 `gan test` 执行（GEP-0007）。因此，一个示例本身就是一条断言，而携带示例的模块则是一个自我验证的产物。生成示例和测试示例是同一个行为；一个跳过后半部分的界面是在有意为之。

服务器应该放在这里而非客户端中的第二个原因：MCP 从函数签名推导工具的 `inputSchema`，而 Gandora 从 `@spec` 推导签名，并从 `@doc`/`@param` 推导描述。Advisor 已经强制执行的注解纪律正是该协议的元数据。契约只需编写一次。

## 范围

涵盖：stdio 服务器、其工具表面、验证流水线、将需求转化为已验证模块的合成器，以及将合成器接入读取需求的代理的项目级配置。超出范围：HTTP 传输、MCP 采样，以及简报之外的提示和资源。

## 术语

**沙盒项目** — 包含一个模块的一次性项目，按请求构建并丢弃。

**原子** — 针对一种语言能力的已验证示例，取自测试套件已经运行的来源。

**组合器** — 由模型支持的从需求到模块的路径。

## 规范

**GEP-0028-R001（服务器）：**`gan-mcp` 通过 stdio 提供 MCP 服务，并且它本身就是一个 Gandora 程序。`GAN_MCP_ROOT` 选择该服务器查询所面向的项目，默认为当前工作目录。

**GEP-0028-R002（不得有未运行之物）：**每个包含代码的答案 MUST 携带产生该答案的判定结果：诊断信息、实践建议，以及执行该模块 doctest 的结果。若答案的模块未达到 `ok: true`，则该答案 MUST 作为携带这些发现的失败结果返回。把未经验证的代码以纯文本形式返回——无论看起来多么合理——都是该接口的缺陷，而非它的降级模式。

**GEP-0028-R003（流水线）：**验证将模块写入沙盒项目中其自身 `defmodule` 所要求的路径（GEP-0001-R013），判定取自 `gan lsc check`（GEP-0025-R009）而非任何私有的重新实现，在硬超时下执行编译产物的 doctest，并在之后删除沙盒。用户的项目绝不被写入。

**GEP-0028-R004（schema 不写两遍）：**工具输入派生自 `@spec`，描述派生自 `@doc` 和 `@param`。工具函数 MUST NOT 接受默认参数（默认参数会抹除所生成的签名），并且 MUST 携带一个精确度足以作为公共契约的 spec。

**GEP-0028-R005（零成本工具）：**`gan_doc`、`gan_pack`、`gan_check` 和 `gan_briefing` 转发已经存在的接口（GEP-0015、GEP-0025、GEP-0026），且 MUST NOT 调用模型。无法凭空发明的内容 MUST NOT 被输出。

**GEP-0028-R006（组合器负责解释与演示）：**`gan_example` 接受一个要演示的特性、语法或能力，返回两项内容：一段文字形式的 **解释**，以及一个 **完整模块**——即一个带 `@moduledoc` 的 `defmodule`，并为每个公共函数提供 `@doc`、`@param`、`@spec` 以及至少一个 `@example` doctest——且已通过 R002。它 MUST NOT 返回裸片段：片段无法被编译、无法运行 doctest、也无法成为 atom，因此根本无法被验证。**答案中的每一行代码 MUST 存在于已验证的模块中。**解释中的代码会是一个伪装成已验证主张的未验证主张，因此该接口会将其剔除。

**GEP-0028-R007（生成前先立足事实）：**组合器的提示词 MUST 携带上下文包以及与该需求相关的 atom。模型被要求基于所提供的事实进行组合，绝不凭记忆回想这门语言。

**GEP-0028-R008（判定驱动投入）：**组合器在首次尝试时以禁用推理的模式运行。唯有失败的判定结果——而非对难度的猜测——才会提高下一次尝试的投入。轮次有上限；当最后一轮失败时，该接口返回这些发现与最接近的已验证 atom，绝不返回最后一版草稿。

**GEP-0028-R009（atom 须挣得）：**一个 atom MUST 来自测试套件所运行的来源——即 std 或 tour 中的某个 `@example`，或一个已通过 R002 的组合模块。通过验证的组合结果 MAY 被记录为 atom；记录它并不免除其在被提供时重新验证的义务。

**GEP-0028-R010（执行模型编写的代码）：**沙盒会运行并非服务器编写的代码。该代码 MUST 在临时目录中、在超时限制下执行，MUST NOT 从用户的项目中被访问到；其失败 MUST 以判定结果的形式呈现，而不是作为异常跨越协议边界。

**GEP-0028-R011（凭据）：**模型配置来自环境变量（`GAN_API_KEY`、`GAN_MODEL`，以及可选的 `GAN_BASE_URL`，默认为供应商端点）。凭据 MUST NOT 被写入日志、回显到判定结果中，或被写入沙盒。

**GEP-0028-R012（项目自行接线）：**`gan init` MUST 以各代理文档规定的格式与位置，写入项目级 MCP 配置，供各个代理自行读取——Claude Code 为 `.mcp.json`，Codex 为 `.codex/config.toml`，opencode 为 `opencode.json`——并且 MUST NOT 覆盖已存在的配置文件。每个此类文件都声明同一条不带路径的命令 `uv run gan mcp`：不含 `cwd`、不含绝对路径、不含环境变量。`uv run` 会从客户端启动所在的任意目录解析出项目环境，`gan` 在该项目的 `.venv/bin`（GEP-0013-R003）中找到 `gan-mcp`，服务器则通过向上逐级查找最近的 `gandora.jsonc` 来发现项目。因此，`gandora-mcp` 是每个通过脚手架创建的项目的开发依赖项。这些文件理应提交到版本库：一旦提交，这套 MCP 接线便对每个克隆仓库的人生效；由此产生的判定结果是项目自己的——在项目自身环境中作出判断，而不是由系统中碰巧安装的工具链来评判。

## 理由

该接口拒绝接受大多数代码生成工具认可的分裂——一条从模型获取答案的快速路径和一条进行检查的慢速路径。在这里，检查*就是*答案：一份 `clean: true` 且 doctest 通过的判定，是区分此服务器与一个已经阅读手册的模型的唯一标准。将这一点设为不可协商（R002），才能让智能体将结果直接交给用户。

R006 选择模块而非片段，因为模块是工具链能够判断的最小单元。片段读起来更短，却无法验证；额外的行数正是证据。将答案一分为二，正是语言已应用于自身文档的同一纪律：`@doc` 是散文，`@example` 会被执行，且没有两者兼得之物。

驱动 composer 的提示词本身就以该语言的 prompt 语法编写——`~p"""` 配合 `<%= %>` 拼接（GEP-0009-R006）——并且它不携带任何手写模块模板。答案的形态由测试套件编译并运行的语料库模块展示，因此流水线中那一段无人验证的代码并不存在。

R008 反转了通常的推理预算问题。当真值验证器在循环中时，一次携带真实诊断的迭代，比在相同猜测上更深入的推敲更有价值——因此努力追随失败而来，而非预判失败。

## 安全与确定性

沙箱执行生成的代码，这与 `gan run` 已代表用户跨越的信任边界相同，但范围收窄为：临时目录、硬超时、无需网络，执行后随即移除。当工具链未变更时，经过验证的答案是可复现的——判定结果和 doctest 输出是关于产物的客观事实，而非关于生成该产物的模型。

## 工具与 AI 使用

MCP 客户端 SHOULD 在每个会话中调用一次 `gan_briefing`，为获取含义而调用 `gan_doc` 或 `gan_pack`，并对其打算移交的每个模块调用 `gan_verify`——包括它自己编写的模块。`gan_example` 适用于需求明确但形式不明确的情况。

## 一致性

测试 MUST 覆盖：一个正确的模块在 doctests 运行并通过后达到 `ok`/`clean`；一个调用不存在的标准库函数的模块，失败并产生产物诊断；一个预期 doctest 输出有误、编译干净却 doctests 失败的模块；模块名到沙盒路径的推导，包括点分名称；从 `@spec` 推导出的工具模式；每个语料库模块都应与其所教导的判定一致；以及组合器要么返回一个解释外加一个通过了 R002 的模块，要么返回一个携带诊断发现的失败——绝不返回未经验证的草案。
