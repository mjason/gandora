# GEP-0019: 自递归尾调用优化

## 摘要

对尾位置的包裹函数调用编译为参数重绑定和循环：

```elixir
def sum_to(0, acc), do: acc
def sum_to(n, acc), do: sum_to(n - 1, acc + n)
```

对于任意 `n` 均在恒定栈上运行，而函数体中的 `recur(args)` 是同一跳转的显式、编译器检查的表达（R005）。Elixir 自然的递归风格在 Python 大约 1000 帧的限制下变得安全。非尾递归（`n * fact(n - 1)`）保持不变——它需要自己的栈。

## Motivation

GEP-0014 为长时间运行的代码提供了 `loop/recur`，因为 Python 没有 TCO，但惯用的 Elixir 代码是以尾递归形式编写的，而如今移植它意味着需要重写每个这样的函数。自递归尾调用可以在静态上被识别，并编译为与 `loop` 已经使用的相同的 `while` 形状——自然的风格应该直接有效。

## 范围

仅限直接自递归。相互递归保持调用栈绑定（蹦床已在 GEP-0014 中被拒绝，且持续被拒绝）。

## Specification

**GEP-0019-R001:** 当调用是子句体的最终表达式、是尾位置上的 `if`/`unless`/`case`/`cond` 分支的最终表达式，或者是尾位置上的代码块的最终表达式时，该调用处于尾位置。`try` 内部、匿名函数以及参数位置中的表达式永远不是尾位置。

**GEP-0019-R002:** 当定义组中的任何子句包含对该组自身名称且元数与组定义匹配的尾调用时，该组将编译为循环：分派（或单个子句的主体）被包装在 `while True:` 中，每个尾自调用成为参数元组的重新绑定加上 `continue`。所有其他退出照常 `return`。可观察行为不变，除了栈深度；百万次迭代的自递归必须在测试中通过（MUST）。

**GEP-0019-R003:** 不在尾位置的自调用编译为普通调用。该优化从不改变求值顺序或参数求值语义；参数在重新绑定之前被完全求值。

**GEP-0019-R004:** 该优化适用于 `def`、`defp` 以及默认参数委托，并且与 `@spec` 注解（GEP-0017）组合不变。

**GEP-0019-R005:** 函数体中的 `recur(args)` 是相同跳转的**显式**写法：它重新绑定包围函数的参数并重新启动它。它必须处于尾位置（MUST），且其元数必须匹配组中的一个子句（MUST）——否则两者都是编译错误，这是隐式形式无法提供的保证（将调用移出尾位置的重构只是静默地丢失优化；而移动的 `recur` 会破坏构建）。分工：自然的 Elixir 尾递归被隐式优化以保持可移植性；`recur` 是*断言*恒定栈的写法。

## Rationale

Rebinding-plus-`continue` 正是 `loop/recur` 编译已有的方式；将其扩展到尾自身调用不会引入新的运行时形态，保持生成代码的可读性（`while True:` + `match`），并使 Elixir 的主导惯用语可以逐字移植。互递归被排除，因为它需要要么一个 trampoline（已被拒绝：不透明、较慢），要么进行整个程序的调用图重写。

## 向后兼容性

保持语义不变；仅堆栈消耗发生变化。

## 安全性与确定性

除 GEP-0001-R024 外，无其他要求；输出保持确定性。

## 工具与AI使用

对于无界迭代，智能体SHOULD编写自然的尾递归，当恒定栈是一个值得断言的要求时，使用函数级`recur`，并在迭代是一种映射而非状态机时，选择`for` (GEP-0020)或Enum。

## 已拒绝的替代方案

### 针对互递归的蹦床（Trampolining）

根据GEP-0014再次拒绝：隐藏了机制，每次跳转产生分配成本，且在生成的输出中可读性差。

### 类似 `@tailrec` 的选择加入注解

分析是静态且安全的；要求注解会使自然写法在被遗忘时静默使用栈绑定。注解本应起的断言作用由显式的 `recur`（R005）承担，后者是经检查的，而非建议性的。

## 符合性

测试必须涵盖：单子句和多子句的尾递归在百万次迭代下；带守卫的子句；在 `if`/`case`/`cond` 中的尾调用；未经优化的非尾自调用（可通过递归限制观察到）；默认值与重绑定的交互；以及一个参考函数在优化前后结果相同。
