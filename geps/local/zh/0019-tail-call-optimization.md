# GEP-0019: 自递归尾调用优化

## Abstract

对尾位置外层函数的调用编译为参数重新绑定和循环：

```elixir
def sum_to(0, acc), do: acc
def sum_to(n, acc), do: sum_to(n - 1, acc + n)
```

对于任意 `n` 在恒定栈上运行，并且函数体中的 `recur(args)` 是同一跳转的显式、编译器检查的写法 (R005)。Elixir 的自然递归风格在 Python 的 ~1000 帧限制下变得安全。非尾递归 (`n * fact(n - 1)`) 保持不变——它需要自己的栈。

## Motivation

GEP-0014 给长时间运行的代码提供了 `loop/recur`，因为 Python 没有 TCO，但惯用的 Elixir 是通过尾递归编写的，而今天移植它意味着要重写每一个这样的函数。自递归尾调用是静态可识别的，并且编译成与 `loop` 已经使用的相同的 `while` 结构——自然的风格应该可以直接工作。

## 范围

仅限于直接自递归。相互递归仍受调用栈限制（蹦床机制已在 GEP-0014 中被拒绝，且持续拒绝）。

## Specification

**GEP-0019-R001:** 一个调用处于尾位置，当它是子句体、处于尾位置的 `if`/`unless`/`case`/`cond` 分支，或处于尾位置的代码块的最后一个表达式时。`try` 内部、匿名函数和参数位置中的表达式从不处于尾位置。

**GEP-0019-R002:** 当定义组的任何子句包含对组自身名称的尾调用，且调用参数数量与组定义的参数数量一致时，该组编译为一个循环：调度（或单个子句体）被包裹在 `while True:` 中，每个尾部自调用变成对参数元组的重新绑定加上 `continue`。所有其他出口照旧 `return`。可观察行为不变，除了栈深度；一百万次迭代的自递归 MUST 在测试中通过。

**GEP-0019-R003:** 不在尾位置的自调用编译为普通调用。该优化从不改变求值顺序或参数求值语义；参数在重新绑定之前被完全求值。

**GEP-0019-R004:** 该优化同样适用于 `def`、`defp` 和默认参数委托，并与 `@spec` 注解（GEP-0017）组合不变。

**GEP-0019-R005:** 函数体中的 `recur(args)` 是相同跳转的**显式**写法：它重新绑定外部函数的参数并重新启动它。它 MUST 处于尾位置，且其参数数量 MUST 与组的一个子句匹配——否则两者均为编译错误，这是隐式形式无法提供的保证（将调用移出尾位置的重构只会静默丢失优化；而移动 `recur` 会破坏构建）。分工：自然的 Elixir 尾递归为了可移植性而隐式优化；`recur` 是*断言*恒定栈的写法。

**GEP-0019-R006:** 每个定义组的编译形状是**可观察的**：当尾递归编译为 `while True:` 重新绑定时，文档查询报告 `"loop"`；当组只在尾位置之外是自递归时，报告 `"stack"`；当不是自递归时，不报告。该形状 MUST 出现在 `gan doc`（本地化文本）、LSP 悬停（徽章行）和 `gan lsc doc`（`tco` 字段）中——开发人员看不到的隐式优化就是他们无法信任的隐式优化。在优化循环内部创建的闭包通过 GEP-0021 快照保留每次迭代的值；该优化永远不会因为闭包而被跳过。

**GEP-0019-R007:** 形状为 `"stack"`（自递归，从未处于尾位置）的定义组会引发一个跨定义的编译**警告**：它将增长 Python 调用栈（约1000帧）。深度由数据形状约束的结构递归——树遍历、嵌套列表展平——是合理的；作者通过在第一个子句前放置 `@allow :stack_recursion` 来确认，这会静默警告并在定义位置记录意图。未被识别的 `@allow` 目标是一个编译错误，因此拼写错误不会静默地重新启用它本应确认的警告。警告携带跨度，并出现在 `gan check`、`gan build` 以及作为编辑器的 Warning 诊断中。

## 理由

重新绑定加`continue`正是`loop/recur`已经拥有的编译方式；将其扩展到尾部自调用不会增加新的运行时形态，保持生成的代码可读性（`while True:` + `match`），并使占主导地位的Elixir惯用语法能够逐字移植。互递归被排除，因为它需要蹦床（被拒绝：不透明且较慢）或整个程序调用图重写。

## 向后兼容性

语义保持不变；仅堆栈消耗发生变化。

## Security and Determinism

除 GEP-0001-R024 外，无其他要求；输出保持确定性。

## 工具与AI使用

代理 SHOULD 为无界迭代编写自然尾递归，当恒定栈是一个值得断言的需求时，使用函数级`recur`，并且当迭代是映射而非状态机时，使用`for`（GEP-0020）或Enum。

## 已否决的替代方案

### 针对相互递归的蹦床机制

根据 GEP-0014 再次否决：隐藏了机制，每次跳转都有分配成本，且在生成的输出中可读性差。

### 类似 `@tailrec` 的选择加入注解

分析是静态且安全的；要求添加注解会导致在忘记时自然拼写会静默地受栈限制。注解本应扮演的断言角色由显式的 `recur` (R005) 填补，它是被检查的而非建议性的。

## 符合性

测试MUST涵盖：在百万次迭代下的单子句和多子句尾递归；带守卫的子句；`if`/`case`/`cond` 中的尾调用；未优化（通过递归限制可观察到）的非尾自调用；默认值与重绑定的交互；以及对于参考函数，优化前后结果相同。
