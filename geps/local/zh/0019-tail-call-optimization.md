# GEP-0019: 自递归尾调用优化

## 摘要

对尾位置的封闭函数的调用会编译为参数重绑定和一个循环：

```elixir
def sum_to(0, acc), do: acc
def sum_to(n, acc), do: sum_to(n - 1, acc + n)
```

对于任何 `n`，该函数在常量栈空间中运行，而函数体中的 `recur(args)` 则是同一跳转的显式且由编译器检查的写法（R005）。Elixir 自然的递归风格在 Python 约 1000 帧的限制下变得安全。非尾递归（`n * fact(n - 1)`）不受影响——它需要自己的栈。

## 动机

GEP-0014 提供了长时间运行的代码 `loop/recur`，因为 Python 没有 TCO，但地道的 Elixir 以尾递归方式编写，而如今移植它意味着需要重写每个这样的函数。自递归尾调用是可静态识别的，并且编译为与 `loop` 已经使用的相同的 `while` 形状——自然风格应该直接工作。

## 范围

仅限直接自递归。互递归仍受调用栈限制（蹦床已在 GEP-0014 中被拒绝，且保持被拒绝）。

## 规范

**GEP-0019-R001：** 当调用是子句体、尾位置上的 `if`/`unless`/`case`/`cond` 分支或尾位置上的块的最终表达式时，该调用处于尾位置。`try`、`loop`、匿名函数内部以及参数位置中的表达式永远不是尾位置。

**GEP-0019-R002：** 当定义组中的任何子句包含对该组自身名称且元数与组定义的元数匹配的尾调用时，该组编译为一个循环：调度（或单个子句的主体）包装在 `while True:` 中，每个尾自调用变为参数元组的重新绑定加上 `continue`。所有其他出口按原样 `return`。可观察行为不变，仅栈深度变化；百万次迭代的自递归 MUST 在测试中通过。

**GEP-0019-R003：** 非尾位置的自调用编译为普通调用。该优化从不改变求值顺序或参数求值语义；参数在重新绑定之前完全求值。

**GEP-0019-R004：** 该优化同样适用于 `def`、`defp` 和默认参数委托，并与 `@spec` 注解（GEP-0017）组合不变。

**GEP-0019-R005：** 在任何 `loop` 之外的函数体中的 `recur(args)` 是同一跳转的**显式**写法：它重新绑定封闭函数的参数并重新启动它。它 MUST 处于尾位置，且其元数 MUST 与组中的某个子句匹配——否则为编译错误，这是隐式形式无法提供的保证（将调用移出尾位置的重构会静默丢失优化；而移动的 `recur` 会破坏构建）。在 `loop` 内部，`recur` 保持其 GEP-0014 含义（最近绑定优先）。分工：自然的 Elixir 尾递归被隐式优化以实现可移植性；`recur` 是*断言*恒定栈的写法。

## 理由

重新绑定加`continue`正是`loop/recur`已经拥有的编译方式；将其扩展到尾自调用不会增加新的运行时形态，保持生成的代码可读（`while True:` + `match`），并且使占主导地位的Elixir惯用法直接可移植。互递归被排除，因为它需要要么是蹦床（被拒绝：不透明、更慢），要么是全局程序调用图重写。

## 向后兼容性

保持语义不变；仅栈消耗发生变化。

## 安全性与确定性

除 GEP-0001-R024 外无其他要求；输出保持确定性。

## 工具与人工智能使用

Agent  SHOULD 为无界迭代编写自然的尾递归，在需要断言恒定栈的需求时使用函数级 `recur`，并将 `loop` 保留给状态机，其中命名状态模式有助于读者理解。

## 被拒绝的替代方案

### 使用蹦床（trampolining）实现互递归

根据 GEP-0014 被再次拒绝：隐藏了机制，每次跳转都产生分配开销，并且在生成的输出中可读性差。

### 类似 `@tailrec` 风格的选择加入注解

该分析是静态且安全的；要求使用注解会使得在忘记使用时，自然写法静默地变为栈边界。注解本应扮演的断言角色由显式的 `recur`（R005）承担，后者是经过检查的而非建议性的。

## 符合性

测试必须涵盖：单子句和多子句尾递归，迭代百万次；守卫子句；`if`/`case`/`cond` 下的尾调用；未优化的非尾自调用（通过递归限制可观察）；默认值与重新绑定的交互；以及参考函数在优化前后结果一致。
