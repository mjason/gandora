# GEP-0016: 格式化器

## 摘要

`gan fmt` 对 Gandora 源码进行规范化：结构缩进、水平空白、空行序列以及尾部空白——除此之外无其他操作。它从不合并或拆分作者的行。其安全契约是机械性的：格式化后的文本 MUST 与原始文本 token 化得到相同的 token 序列（包括注释），否则文件保持不变。该格式化程序是 `gandora-tool` 内部的一个 Gandora 程序，基于新的无损 `gandora_core.tokens` API 构建——编译器仍然是词法正确性的唯一来源。

## 动机

格式化程序终结了样式争论，并为代理（agents）提供了确定性的目标。其保守范围——缩进和空格，通过令牌往返（token round-trip）验证——实现了完整美观打印程序（pretty-printer）的大部分价值，且没有任何风险：格式化程序无法损坏它无法重新进行相同令牌化的程序。

## 范围

空白层级格式化及其背后的令牌API。行重新换行、注释重新流动以及AST级规范化（括号插入、调用风格变更）属于未来修订。

## 术语

- **结构缩进（Structural indent）**：由 `do`/`end`、`fn`、括号以及子句箭头嵌套所赋予某行的列位置。
- **续行（Continuation line）**：延续上一表达式的一行（以 `|>` 或二元运算符开头，或者跟随以 `=` 或二元运算符结尾的行）。

## 规范

**GEP-0016-R001：** `gandora_core.tokens(text, path \\ "nofile")` 返回完整的词法流，作为一系列 `%{"kind" => k, "text" => t, "line" => l, "col" => c, "end_line" => el, "end_col" => ec}` 映射的列表，包括 `comment` 标记和 `newline` 标记，按源顺序排列。`tokens` MUST 足够无损，使得标记种类/文本加上跨度间的空白能够重建文件。解析继续忽略注释。

**GEP-0016-R002：** `gan fmt [path ...]` 就地格式化 `.gan` 文件（未指定路径时，格式化项目 `source` 目录）；`gan fmt --check [path ...]` 不写入任何内容，如果任何文件会发生变化，则退出码为 1。输出和退出码遵循 GEP-0001-R023。

**GEP-0016-R003：** 格式化程序仅重写：缩进（每个结构级别两个空格）；二元运算符周围和逗号（在类似字符串的标记之外）后的空格；尾部空白；两个或更多空行的连续行（折叠为一个）；以及缺失的末尾换行符。它 MUST NOT 连接行、拆分行，或更改字符串、heredoc 或 sigil 主体的内部，除了 R005 的统一移位和 R008 的捕获括号化。

**GEP-0016-R004：** 结构缩进：`do`、`fn` 以及每个未闭合的括号增加一个缩进级别；`end` 和闭合括号在它们开始的行的上方弹出；`else`、`rescue` 和 `after` 行位于其块主体下方一个级别。以 `->` 结尾的行打开一个子句主体，深度为一个级别，由下一个子句头、`end` 或闭合括号关闭。延续行位于其锚点下方一个级别。仅注释行的缩进取其所处位置的结构缩进。

**GEP-0016-R005：** 多行字符串、heredoc 或 sigil 主体作为一个整体移动：每一内部行和闭合定界符的缩进恰好偏移应用于起始行的缩进增量，逐字节保留 GEP-0001-R026 的缩进移除后的值。

**GEP-0016-R006：** 在替换文件之前，格式化程序 MUST 验证新文本的注释序列与原始文件相同（尾部空白除外），并且 `gandora_core.parse` 对旧文本和新文本产生相等的引用项。如果不匹配，它 MUST 保持文件不变，并报告一个引用此规则的内部错误。格式化 MUST 是幂等的：`fmt(fmt(s)) == fmt(s)`。

**GEP-0016-R007：** 格式化程序用 Gandora 实现，位于 `gandora-tool` 中，作为本地运行器命令（GEP-0013-R002 系列）；它仅使用 R001 的令牌 API——不使用私有编译器状态。

**GEP-0016-R008：** 捕获主体的开头是 `$` 引用时，会被括号括起来：`&$math.sqrt/1` 变为 `&($math.sqrt/1)`——这是唯一插入令牌的重写，受 R006 的解析检查覆盖。其他捕获拼写保持原样。

## 理由

采用令牌验证的保守策略而非漂亮打印机：完整的格式化程序需要编译器不保留的带有注释的具体语法树，其失败模式是静默损坏。R006 将最坏情况转化为带有错误消息的无操作。保留作者换行符尊重了语言所鼓励的管道密集型风格，其中行结构即是意义。

## 向后兼容性

增量式：一个新的核心API，一个新的运行器命令。

## Security and Determinism

格式化程序仅读取和写入项目源代码，不执行任何操作，并且对文件内容是确定性的。

## 工具与AI使用

代理（Agent）在生成代码后 SHOULD 运行 `gan fmt`，且 MUST NOT 依赖格式敏感的差异（diff）。`--check` 是CI界面。

## 被拒绝的替代方案

### 完整的AST美观打印机（mix format风格）

需要一个无损的具体语法树，附带注释——即第二个解析器。推迟到令牌级格式化程序证明需求之后。

### 在Rust中实现fmt

Gandora工具链中的程序（GEP-0013）正是为此类工具而存在的；编译器只提供令牌API，其他什么都不做。

## Conformance

测试 MUST 覆盖：涵盖每条 R003/R004/R005 规则的 fixture 文件；在每个 fixture 和仓库自身源码上的幂等性；R006 验证（故意破坏的改写会被拒绝）；`--check` 退出码；以及重新缩进下 heredoc 值的保留。
