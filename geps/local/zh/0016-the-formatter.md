# GEP-0016: 格式化器

## 摘要

`gan fmt` 规范化 Gandora 源码：结构缩进、水平空白、空行序列和行尾空白——外加一种结构性重排：跨行的映射字面量会采用规范的每行一对形式（R011）。它从不合并作者的换行，也只在上述位置拆分换行。其安全约定是机械性的：格式化后的文本 MUST 与原文本在词法上得到相同的 token 序列（含注释），否则文件保持原样不动。该格式化程序是 `gandora-tool` 内的一个 Gandora 程序，构建于新的无损 `gandora_core.tokens` API 之上——编译器始终是词法真相的唯一来源。

## 动机

格式化器终结了风格之争，为智能体提供了确定性目标。保守的范围——缩进与空白，经 token 往返验证——提供了完整美化打印器的大部分价值，却不承担其任何风险：格式化器缺陷无法破坏一个无法以相同方式重新分词的程序。

## 范围

空白级别的格式化及其背后的 token API。行的重新换行、注释的重新编排，以及 AST 级规范化（括号插入、调用风格更改）留待未来的修订。

## 术语

- **结构缩进**：由 `do`/`end`、`fn`、括号和子句箭头的嵌套为某行分配的列。
- **续行**：延续前一个表达式的行（以 `|>` 或二元运算符开头，或跟随以 `=` 或二元运算符结尾的行）。

## 规范

**GEP-0016-R001：** `gandora_core.tokens(text, path \\ "nofile")`
返回完整词法流，形式为 `%{"kind" => k, "text" => t, "line" => l, "col" => c, "end_line" => el,
"end_col" => ec}` 映射的列表，并按源码顺序包含 `comment` 标记和 `newline`
标记。`tokens` MUST 做到足够无损，使得标记种类/文本以及各片段之间的空白能够重构出该文件。解析过程仍然忽略注释。

**GEP-0016-R002：** `gan fmt [path ...]` 原地格式化 `.gan` 文件
（未给出路径时格式化项目的 `source` 目录）；
`gan fmt --check [path ...]` 不写入任何内容，若任一文件会被更改则退出 1。输出与退出码遵循 GEP-0001-R023。

**GEP-0016-R003：** 格式化器只重写以下内容：
缩进（每个结构层级两个空格）；字符串类标记之外的二元运算符周围及逗号之后的空格；行尾空白；
连续两行或更多空行（折叠为一行）；以及缺失的文件末尾换行符。它 MUST NOT 合并行，也 MUST NOT 拆分行——
除非 R011 规定；它 MUST NOT 改动字符串、heredoc 或 sigil 正文的内部，除非是 R005 的统一位移和 R008 的捕获加括号。

**GEP-0016-R004：** 结构缩进：`do`、`fn` 以及每个未闭合的括号推进一层；`end` 和闭合括号在它们起始的行之前弹出；
`else`、`rescue` 和 `after` 行位于其块体低一层的位置。以 `->` 结尾的行会打开缩进一层子句体，
由下一个子句头、`end` 或闭合括号关闭。续行位于其锚点低一层的位置。仅含注释的行采用其所处位置的结构缩进。

**GEP-0016-R005：** 多行字符串、heredoc 或 sigil 正文作为一个整体移动：每一内部行和结束定界符
都精确位移应用到其起始行的缩进增量，从而逐字节保留 GEP-0001-R026 去除缩进后的值。

**GEP-0016-R006：** 在替换文件之前，格式化器 MUST 验证：新文本的注释序列与原文件相同（不计行尾空白），
并且 `gandora_core.parse` 对旧文本和新文本产生相等的引用项。若不一致，它 MUST 保持文件不变，
并以命名此规则的内部错误进行报告。格式化 MUST 是幂等的：`fmt(fmt(s)) == fmt(s)`。

**GEP-0016-R007：** 格式化器在 Gandora 内部实现，位于 `gandora-tool` 中，作为原生运行器命令
（GEP-0013-R002 系列）；它只使用 R001 的 token API——不依赖任何私有编译器状态。

**GEP-0016-R008：** 正文以 `$` 引用开头的捕获会被加括号：`&$math.sqrt/1` 变为 `&($math.sqrt/1)`——
这是唯一插入标记的重写，由 R006 的解析检查覆盖。其他捕获写法保持原样。

**GEP-0016-R009：** `gan fmt -` 从 stdin 读取文档并将其规范形式写入 stdout——
这是管道与编辑器集成的拼写。R006 验证仍然约束输出：失败时输入原样通过，向 stderr 写入一条说明，
退出码为 2。干净运行无论是否有改动都退出 0。

**GEP-0016-R010：** `gan fmt --diff [path ...]` 打印格式化将要产生改动的统一 diff，
并且不重写任何内容；当任一文件会改动时退出 1，否则退出 0，与 `--check` 的契约一致并附带证据。

**GEP-0016-R011（多行映射只采用一种形状）：** 标记跨越多于一行 `%{` 映射字面量会被重排为规范形式：
起始定界符保留在作者放置的位置；每个顶层键值对在其自身行开始，且缩进深一层；
闭合 `}` 在起始定界符的缩进层级上从自身行开始，并保留其后跟随的标记（`)`、`,`）。
单行映射不受影响——能否放在一行由作者决定；如何换行则不由其决定。跨度内包含注释或多行字符串/heredoc/sigil
的映射保持原样：移动这些内容不是格式化器的事。该重写只拆分行，R006 验证原样适用于它。

## 理由

经词法单元验证的保守策略，而非美化打印器：完整的美化打印器需要一棵附带注释的具体语法树，而编译器并不保留这棵树，且其失效模式是静默损坏。R006 将最坏情况转化为带有错误消息的空操作。保留作者的换行，顺应了该语言所鼓励的重管道风格，在那里行结构即意义。

## 向后兼容性

新增：一个核心 API 和一个 runner 命令。

## 安全性与确定性

格式化器仅读取和写入项目源代码，不执行任何代码，并且对文件内容具有确定性。

## 工具与 AI 使用

智能体 SHOULD 在生成代码后运行 `gan fmt`，且 MUST NOT 依赖
对格式敏感的差异。`--check` 是 CI 的接口。

## 被拒绝的备选方案

### 完整的 AST 美化打印器（mix format 风格）

需要一个带有附加注释的无损具体语法树——也就是说，需要第二个解析器。推迟到 token 级格式化器证明其需求之后。

### 用 Rust 实现 fmt

Gandora 中的工具链项目（GEP-0013）正是为此类工具而存在的；编译器只提供 token API，除此之外不提供任何东西。

## 一致性

测试 MUST 覆盖：针对每条 R003/R004/R005 规则的 fixture 文件；在所有 fixture 及仓库自身源码上的幂等性；R006 验证（故意破坏的重写会被拒绝）；`--check` 退出码；重新缩进时 heredoc 值的保留；R009 stdin 往返及其退出码；以及使文件保持不变的 R010 diff 运行。
