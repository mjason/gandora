# GEP-0016: 格式化器

## 摘要

`gan fmt` 规范化 Gandora 源码：结构缩进、水平空白、空行序列以及尾随空白——仅此而已。它从不合并或拆分作者的行。其安全合约是机械性的：格式化后的文本 MUST 与原文标记化后得到相同的标记序列（包括注释），否则文件保持不变。格式化器是 `gandora-tool` 内部的一个 Gandora 程序，构建于新的无损 `gandora_core.tokens` API 之上——编译器仍然是唯一的词法真实来源。

## 动机

格式化程序终结了风格争论，并为代理提供了确定性的目标。保守的范围——缩进和空白，通过令牌往返验证——提供了完整漂亮打印器的大部分价值，且没有任何风险：格式化程序无法破坏它无法重新进行相同令牌化的程序。

## 范围

空白级别格式化及其背后的令牌API。行重排、注释重排以及AST级规范化（括号插入、调用风格变更）属于未来版本。

## 术语

- **结构缩进**：由 `do`/`end`、`fn`、括号以及子句箭头嵌套所赋予某行的列位置。
- **延续行**：延续前一行表达式的行（以 `|>` 或二元运算符开头，或者跟在以 `=` 或二元运算符结尾的行之后）。

## 规范

**GEP-0016-R001：** `gandora_core.tokens(text, path \\ "nofile")`
返回完整的词法流，形式为 `%{"kind" => k, "text" => t, "line" => l, "col" => c, "end_line" => el, "end_col" => ec}` 映射的列表，按源代码顺序包含 `comment` 标记和 `newline` 标记。`tokens` MUST 足够无损，以便通过标记种类/文本加上跨度之间的空白重构文件。解析继续忽略注释。

**GEP-0016-R002：** `gan fmt [path ...]` 原地格式化 `.gan` 文件（未指定路径时使用项目 `source` 目录）；`gan fmt --check [path ...]` 不写入任何内容，若任何文件会发生变化则退出码为 1。输出和退出码遵循 GEP-0001-R023。

**GEP-0016-R003：** 格式化程序仅重写以下内容：缩进（每个结构层级两个空格）；二元运算符周围和逗号后（不在类字符串标记内部）的空格；尾部空白；两个或更多连续空行（压缩为一个）；以及缺失的末尾换行符。它 MUST NOT 合并行、拆分行，或更改字符串、heredoc 或 sigil 体的内部内容，除了 R005 的统一移位和 R008 的捕获括号化。

**GEP-0016-R004：** 结构缩进：`do`、`fn` 和每个未闭合的括号推进一个层级；`end` 和闭合括号在它们开始的行之前弹出层级；`else`、`rescue` 和 `after` 行位于其块体下方一个层级。以 `->` 结尾的行开启一个子句体，深入一个层级，由下一个子句头部、`end` 或闭合括号闭合。续行位于其锚点下方一个层级。纯注释行采用其所在位置的结构缩进。

**GEP-0016-R005：** 多行字符串、heredoc 或 sigil 体作为一个整体移动：每个内部行和闭合定界符精确移动应用于开行行的缩进增量，保持 GEP-0001-R026 的去除缩进值逐字节不变。

**GEP-0016-R006：** 在替换文件之前，格式化程序 MUST 验证新文本的注释序列与原文件相同（忽略尾部空白），且 `gandora_core.parse` 对新旧文本产生相等的引号项。如果不匹配，它 MUST 保持文件不变，并报告一个引用此规则的内部错误。格式化 MUST 是幂等的：`fmt(fmt(s)) == fmt(s)`。

**GEP-0016-R007：** 格式化程序在 Gandora 内部实现，位于 `gandora-tool` 中，作为原生运行器命令（GEP-0013-R002 系列）；它仅使用 R001 标记 API——不使用私有编译器状态。

**GEP-0016-R008：** 主体以 `$` 引用开始的捕获会被括号化：`&$math.sqrt/1` 变为 `&($math.sqrt/1)`——这是唯一插入标记的重写，受 R006 解析检查覆盖。其他捕获拼写保持不变。

**GEP-0016-R009：** `gan fmt -` 从标准输入读取文档，并将其规范形式写入标准输出——这是管道和编辑器集成的拼写。R006 验证仍然控制输出：失败时输入原样通过，注释发送到标准错误，退出码为 2。干净运行退出码为 0，无论是否有任何变化。

**GEP-0016-R010：** `gan fmt --diff [path ...]` 打印格式化会更改的统一差异，不重写任何内容；若任何文件会发生变化，则退出码为 1，否则为 0，与 `--check` 的契约一致，并附带证据。

## Rationale

基于令牌验证的保守策略优于美化打印器：完整的格式化工具需要编译器不保留的注释附加具体语法树，且其失败模式是静默损坏。R006 将最坏情况变成带错误消息的空操作。保留作者原有的换行尊重了该语言所鼓励的管道密集型风格，其中行结构即是意义。

## 向后兼容性

新增内容：一个核心API，一个运行器命令。

## 安全与确定性

格式化程序仅读取和写入项目源代码，不执行任何操作，并且对文件内容具有确定性。

## 工具与AI使用

代理 SHOULD 在生成代码后运行 `gan fmt`，并且 MUST NOT 依赖于格式敏感的差异。`--check` 是 CI surface.

## 被拒绝的替代方案

### 完整的AST漂亮打印机（mix format风格）

需要无损的具体语法树并附带注释——即第二个解析器。推迟到token级格式化器证明需求后。

### 在Rust中实现fmt

Gandora中的工具链程序（GEP-0013）正是为此类工具而存在的；编译器只提供token API，不提供其他任何东西。

## 符合性

测试 MUST 覆盖：测试每个 R003/R004/R005 规则的夹具文件；对每个夹具和仓库自身源代码的幂等性测试；R006 验证（故意损坏的重写被拒绝）；`--check` 退出码；重新缩进下的 heredoc 值保留；一个带退出码的 R009 标准输入往返测试；以及一个保持文件不变的 R010 差异运行。
