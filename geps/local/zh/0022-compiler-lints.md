# GEP-0022：编译器提示

## 摘要

编译器会像 rustc 那样，在能够静态证明代码不安全或不可达时发出警告：读取后无任何绑定的变量（必然引发 `NameError`）、从未使用的绑定、永远无法匹配的分句、其结果被丢弃的推导式、没有任何引用的私有函数。警告是基于范围的诊断——`gan check`、`gan build` 和编辑器波浪线均指向有问题的定义——且每个 lint 要么有惯用修复（`_` 前缀），要么有显式确认（`@allow`，即 GEP-0019-R007 的机制）。

## 动机

Python 将名称解析推迟到运行时，因此拼写错误的变量会导致生产环境崩溃，而不是编译错误——这给工具链本身带来了麻烦（一个 LSP 处理程序随附了一个 `NameError`，而编译器对此保持沉默）。这里的每个 lint 仅在静态可证明的事实上触发；没有一个是风格意见。

## 范围

编译器中的函数级数据流 lint 检查。跨模块分析、基于类型的 lint 检查以及可配置的 lint 级别是未来的 GEP。

## 规范

**GEP-0022-R001（未定义变量）：** 在函数中读取的变量，若没有参数、模式、pyimport 名称或模块函数对其进行绑定，则发出警告并指明该变量。当模块使用 `import Mod`（裸名称变得静态不可知）时，该模块的 lint 检查将停止。模式绑定出现不算读取；引脚（`^x`）和模板标签拼接（`<%= x %>`，GEP-0009-R002）算作读取。

**GEP-0022-R002（未使用的绑定）：** 绑定的变量（参数或模式）从未被读取，则发出警告，并建议使用 `_` 前缀。以 `_` 开头的名称和宏卫生名称不受此规则约束。使用情况的判断跨越整个定义组——任何子句中的读取都算在内。

**GEP-0022-R003（不可达的子句）：** 没有守卫的子句，其模式全部是裸变量，会匹配任何参数；其后具有相同元数的子句——以及 `case` 子句中位于无守卫的捕获/通配符之后的子句——永远无法执行，并发出警告。

**GEP-0022-R004（被丢弃的推导式）：** 处于语句位置的 `for` 推导式会构建一个无人读取的集合；代理和人类 alike MUST 使用 `Enum.each` 实现副作用（GEP-0020）。编译器会在推导式处发出警告。

**GEP-0022-R005（未使用的私有函数）：** 某个 `defp` 组没有被其他定义、装饰器或模块属性引用，则发出警告。若有意保留，可使用 `@allow :unused_function` 确认（未知的 `@allow` 目标仍按 GEP-0019-R007 视为编译错误）。

## 理由

只有可证的事实才会发出警告，因此 lint 保持可信：R001 是确定的崩溃，R003/R005 是确定的死代码，R004 是 GEP 已经禁止的确定浪费，而 R002 的 `_` 约定是 Elixir 自身的约定。当合法代码可能触发 lint 时（GEP-0019-R007 中的结构递归，此处保留供以后使用的私有函数），解决方法是在定义处显式添加注释——可搜索、可审查的意图，绝无全局开关。

## Backwards Compatibility

仅警告；编译输出无变化。现有代码可能会发出警告 — 修复方法是添加 `_` 前缀、删除或用 `@allow` 注解。

## 安全性与确定性

除 GEP-0001-R024 外无其他要求；lint 检查是确定性的。

## 工具与AI使用

Agents MUST 将这些警告视为需要修复的缺陷，而非忽略的噪音，且 SHOULD NOT 添加 `@allow` 而不说明被标记的代码是有意为之。

## 被否决的备选方案

### 未定义函数（裸调用）检查

裸被调用函数名涵盖整个内置接口；在此处枚举它会将 lint 与每一个未来的内置函数耦合。已推迟。

### 可配置的 lint 级别

统一行为保持输出跨机器和 CI 的可移植性；每个站点的 `@allow` 覆盖了合理的例外情况。

## 一致性

测试 MUST 覆盖：未定义读取警告及其 pyimport/`import` 抑制；使用 `_` 豁免和符号拼接读取的未绑定变量；带守卫和跨元数非警告的不可达 def 与 case 子句；被丢弃的推导式；未使用的 defp，及其被引用和 `@allow` 认可的静默。
