# GEP-0005: 符号

## 摘要

魔符是 Elixir 的 `~name<delimiter>body<delimiter>` 字面量族。本提案为 v0 表面增加了四个：`~w`（单词列表）、`~s`（自由分隔符选择的字符串）、`~r`（编译后的正则表达式）以及 `~python`——一个原始魔符，将逐字 Python 表达式拼接进生成的代码中。`~python` 是逃生舱，当宿主语言已能直接表达某些内容时，保持编译器小巧。作为一个表达式，`~python` 的值像其他任何值一样绑定和返回。

## 动机

单词列表和正则表达式是日常使用的字面量，其纯字符串拼写方式显得杂乱（如 `["a", "b", "c"]`、模式中的转义反斜杠）。更重要的是，一门编译到 Python 的语言需要一个有原则的逃生口：当某个 Python 表达式没有 Gandora 拼写形式（例如推导式、`yield`、异类运算符）时，作者应当直接嵌入该表达式，而非将其封装在 Python 辅助模块中。带语言标签的嵌入式语言主体可以干净地解决这一问题，就像 Elixir 的 sigil 语法那样。

## 范围

上述四个符号、它们的分隔符集以及原始模式与插值模式的分割。自定义用户定义符号、符号修饰符（`~r/x/i`）、类型化的 `extern` 句柄、基于文件的嵌入以及额外的符号（`~D` 日期，`~U` 时间戳）被推迟。

## 术语

- **征记（Sigil）**：一个字面量 `~name` 后跟一个带分隔符的主体。
- **插值征记（Interpolating sigil）**：小写名称的征记，其主体支持 `#{...}` 插值。
- **原始征记（Raw sigil）**：主体按原样取用的征记：每个大写名称的征记以及嵌入式语言征记 `~python`。

## 规范

**GEP-0005-R001:** 符咒是 `~` 后面紧跟一个字母名称和一个带分隔符的主体。支持的分隔符对包括 `( )`、`[ ]`、`{ }`，以及对称的 `/ /`、`" "`、`| |`，还有三引号 `""" """`。括号类分隔符可以嵌套；对称分隔符不能嵌套。

**GEP-0005-R002:** 在每个符咒主体中，反斜杠逐字传递，但反斜杠可以转义结束分隔符（并且 `\\` 在结束分隔符前表示一个字面反斜杠）。插值符咒额外支持 `#{expr}`；原始符咒将 `#{` 视为文本。小写名称会进行插值，但 `~python` 除外，其主体是原始宿主代码。

**GEP-0005-R003:** 紧跟在结束分隔符之后的字母（一个 Elixir 符咒修饰符）MUST 产生一个诊断，说明不支持修饰符。

**GEP-0005-R004:** `~w(one two three)` 求值为由空白分隔的单词列表，即 `["one", "two", "three"]`。启用插值时，分割会在运行时对插值后的字符串进行。

**GEP-0005-R005:** `~s(...)` 求值为一个字符串，与双引号字符串相同，但分隔符更自由。

**GEP-0005-R006:** `~r(...)` 求值为一个编译后的正则表达式：它编译为 `re.compile(<body>)`，并隐式包含 `import re`。主体按字节原样传递给 Python 的 `re` 引擎（根据 R002 调整），因此 Python 正则表达式语法（而非 Erlang 的）是约定。

**GEP-0005-R007:** `~python(...)` 是一个原始符咒，其主体 MUST 是单个 Python 表达式；编译器将其逐字拼接，用括号包裹，插入到符咒表达式位置生成的代码中。编译器除了非空检查外不进行任何主体验证；错误由 Python 抛出。在符咒位置作用域内的 Gandora 绑定，通过 GEP-0001-R015 的名称映射对主体可见。

**GEP-0005-R008:** `~python` 主体对编译器是不透明的：宏卫生不重命名其中的名称，工具 MUST 将其视为 Python 而非 Gandora。在 v0 中，`~python` 主体 MUST NOT 由宏展开生成。

**GEP-0005-R009:** *被 GEP-0009-R001 废除*：每个非内建名称现在都是嵌入式语言符咒。

**GEP-0005-R010:** 一个或两个字符的符咒名称 MUST 是功能白名单 `~w ~s ~r ~p` 之一；任何其他短名称都会导致编译错误，并列出该白名单。三个或更多字符的名称是语言标记的文本符咒（GEP-0009-R001），并且始终有效。

## 设计理由

原始字符串与插值字符串的区分完全遵循 Elixir 的做法，因此知识可迁移。反斜杠直通（而非完整的转义处理）使得 `~r(\d+)` 无需双重转义即可书写；这与 Elixir 处理 sigil 主体的方式一致。

`~python` 有意编译为带括号的逐字拼接，而非 `eval` 或辅助函数调用：输出的代码保持可读性、零运行时开销，并且行为与手写的 Python 代码完全相同。宿主语言是一种特性，而非失败模式——此处限制为单个表达式，以确保拼接不会破坏周围语句的结构。语句级嵌入（函数、类）仍然是普通 Python 模块加上 `pyimport` 的职责。

## 向后兼容性

纯附加性；`~` 此前是无效字符。

## 安全性与确定性

Sigils 是字面量；编译过程保持零执行。`~python` 将作者编写的文本拼接到生成的输出中，就像手写的 Python 文件会包含它一样——它不会授予项目自身的 Python 文件所缺少的任何能力。生成的输出保持确定性。

## 工具与人工智能使用

代理应优先使用 `~w`/`~r` 而非手动构建的等价物，仅在 Python 表达式没有 Gandora 拼写时才使用 `~python`，并保持 `~python` 主体为一个可读的表达式——任何更长的内容应归属于通过 `pyimport` 导入的 Python 模块。

## 被拒绝的替代方案

### 编译 `~r` 为 Gandora 侧的 regex AST

可移植的正则表达式模型会将表面与 Python 解耦，但目标就是 Python，其 `re` 模块无论如何都是运行时；重新编码正则表达式语法毫无益处，并且破坏了从 Python 的复制粘贴。

### 用于语句的 `embed python do ... end` 块形式

语句级嵌入会重复普通 Python 模块的 `pyimport` 已经做得好的功能，并且会引入非结构化代码注入到模块作用域中。仅表达式的符号保持了逃生出口的狭小。

### 在符号体中进行完整的 Elixir 转义处理

在 `~r` 内部处理 `\n` 等字符会迫使正则表达式作者对每个反斜杠进行双重转义，这是经典的符号失败；直通匹配符合 Elixir 的实际行为和正则表达式的预期。

## 未解决的问题

本次修订无未决问题。

## 一致性

测试 MUST 覆盖：每个分隔符对，包括嵌套和转义闭分隔符；`~w`/`~s`/`~r` 中的插值以及 `~python` 中无插值；单词分割（字面量和运行时）；保留反斜杠的 `re.compile` 输出；`~python` 在表达式位置中的拼接，包括在管道和调用内部；修饰符诊断（R003）；以及未知符号诊断（R009）。
