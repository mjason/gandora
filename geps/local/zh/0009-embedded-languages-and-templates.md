# GEP-0009: 嵌入式语言和模板

## 摘要

`~python` 是某一范式的一个实例，而非特例：任何 `~<lang>` 符号（`~markdown`、`~sql`、`~html` 等）都会嵌入一个以该语言标记的原始正文。每个嵌入的正文都支持 EEx 风格的拼接：`<%= expr %>` 插入一个 Gandora 表达式。对于 `~python`，拼接内容为代码（编译后的表达式文本，与之前相同，但现在是可参数化的）；对于其他所有语言，该符号会求值为一个包含运行时拼接值的字符串。一种机制涵盖了嵌入式语言家族和 EEx 的模板标记。

## 动机

原始嵌入体（GEP-0005）故意抑制 `#{}` 插值，因为 `#` 和 `{` 在大多数目标语言中有特定含义。但实际的嵌入内容需要参数——SQL 查询的表名、基于 Gandora 绑定和计算片段的 Python 表达式、带有数值的 Markdown 报告。EEx 的 `<%= %>` 标记在实践中无冲突，为人熟悉，且在不同语言中表现一致。

## 范围

内嵌的符号族、`<%= %>` 拼接和语言标记。
EEx 语句/循环标签（`<% %>`）、`.eex` 模板文件、布局和每种语言的验证被推迟。

## 术语

- **嵌入符号**：其名称不是 GEP-0005 内置符号（`w`、`s`、`r`）之一的符号；其名称是语言标签。
- **拼接**：`<%= expr %>` 标记，包含一个 Gandora 表达式。

## 规范

**GEP-0009-R001:** 任何非内置名称的符号都是嵌入式符号。其主体是原始的（GEP-0005-R002 反斜杠规则；无 `#{}` 插值）。GEP-0005-R009 的未知符号诊断被废除。语言标签是用于工具（高亮、未来验证）的编译时元数据；编译器不解释主体语言。

**GEP-0009-R002:** 在每个嵌入式主体内部，`<%= expr %>` 包含一个 Gandora 表达式，该表达式使用符号作用域内的绑定进行解析和编译。标记内的空白被忽略；`<%%=` 转义字面量 `<%=`。拼接 MUST 是单个表达式；解析失败是命名该符号的编译错误。

**GEP-0009-R003:** `~python` 保持其 GEP-0005-R007 语义——主体按原样拼接为生成的代码中的一个表达式——每个 `<%= expr %>` 被替换为编译后的表达式文本（带括号）。它仍然是唯一一个主体作为代码进入程序的符号。

**GEP-0009-R004:** 其他所有嵌入式符号均求值为字符串：主体文本中每个拼接被替换为其表达式的运行时值，格式如同 `#{}` 插值（当存在拼接时编译为 f-string，否则为普通字面量）。

**GEP-0009-R005:** 多行嵌入式主体使用 GEP-0005 分隔符，包括 `"""`；拼接工作方式相同。`"""` 主体遵循 GEP-0001-R026 的 heredoc 缩进去除语义——开头的换行符被丢弃，并且每行中关闭分隔符的缩进被移除——因此模板在模块内部自然缩进，同时生成左对齐的值。在该词法修剪之外，生成的输出 MUST 在拼接之外逐字节保留主体文本。

## 基本原理

一种标记适用于所有语言，胜过每种语言各自定义插值规则；而 `<%= %>` 是 Elixir 中既有的写法（EEx）。`~python` 的代码拼接与其他语言的值拼接，分别对应各自主体*实际*是什么：`~python` 主体执行，其他主体是数据。不验证的语言标签让编译器保持小巧，同时为工具提供稳定的挂钩点。

## 向后兼容性

取消了未知符号错误（新增特性：之前被拒绝的程序变为有效）。`~python`主体中包含字面文本`<%=`的必须切换为`<%%=`；其他现有表面无变化。

## Security and Determinism

Splices 是普通的编译表达式；嵌入的主体在编译时保持为惰性文本。`~python` 保留其原有的审计表面：作者编写的代码在输出中可见。

## 工具与 AI 使用

Agent 应使用 `~sql`/`~markdown`/ 等表示嵌入内容，而非拼接字符串；使用 `<%= %>` 进行参数化，并且绝不要从不可信字符串构建 `~python` 代码——拼接在其它语言中插值的是*值*，但在 Python 中插值的是*代码*。

## 被拒绝的替代方案

### 在嵌入体中启用 #{}

与目标语言语法冲突（`#` 注释、`{}` 块、Python 字典/集合显示）——这正是原始体存在的原因。

### 现在引入完整的 EEx 引擎

语句标签、布局和文件模板是一个库级别的表面；值/代码拼接涵盖了语言层面的需求，未来的 GEP 可以在不改变此契约的前提下，在此基础上添加 `EEx` 类工具。

## 开放问题

此版本无。

## 符合性

测试必须覆盖：任意语言标记（sigil）求值为其精确主体；值的拼接（包括包含管道和互操作调用的表达式）编译为 f-字符串；`~python` 代码拼接；`<%%=` 转义；多行 `"""` 主体；单表达式诊断；以及拼接外部的字节保留。
