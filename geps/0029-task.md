# GEP-0029: Task

## Abstract

`Task` is Gandora's library over Python's coroutine world: `run`
enters it from the synchronous rim, `async` spawns, the language's
own `await` (GEP-0030) joins, and everything above a bare join —
deadlines with tuple verdicts, ordered fan-out, bounded streams,
combinators, cancellation, the bridge to blocking code — is an
ordinary std module of thin `asyncio` wrappers. One world, stated
plainly: threads are no longer a parallel Task universe, just the
`blocking` bridge inside this one.

## Motivation

Revisions 1–4 built Task on `concurrent.futures`: an Elixir-shaped
thread-pool vocabulary, with coroutines forced across a `from_async`
bridge onto a hidden background event loop. It worked, and its costs
were structural: a daemon thread owning an invisible loop; anyio's
single-task lifecycles constraining what could cross the bridge; a
whole family of honest but ugly footnotes ("a running thread cannot
be killed"); and — once GEP-0030 rev 3 layered `@async` on top — one
vocabulary that compiled differently per world.

Gleam names the mistake: each target's library exposes that target's
native model thinly (`gleam/javascript/promise` wraps the Promise JS
already has), and no world simulates another. Modern Python reached
the same verdict from the other side — its own guidance is asyncio
for structure and `to_thread` for the blocking edge, not thread pools
as the primary model. With native `async def`/`await` in the language
(GEP-0030 rev 4), the thread world stops being load-bearing: Task
drops to the coroutine world's natural shape, and every wrapper it
keeps is one readable line over `asyncio`.

What Task adds over raw asyncio interop is the API worth having:
millisecond deadlines that return `{:ok, v}` / `{:error, :timeout}`
tuples instead of raising, ordered joins, bounded streams, Gleam's
combinators, and cancellation that actually cancels — which threads
never could.

## Scope

Covered: the `Task` std module — `run/1`, `async/1`, `blocking/1`,
`all/1`, `try_await/2`, `try_all/2`, `async_stream/3`, `map/2`,
`tap/2`, `recover/2`, `race/1`, `shutdown/1`, `sleep/1`,
`completed/1`. Out of scope: the syntax it rides on (GEP-0030),
supervision and links (BEAM property; asyncio has no equivalent and
none is imitated), and thread pools as a user-facing model — blocking
work enters through `blocking/1`, not through a second Task.

## Terminology

**Task** — a handle for spawned work; concretely an `asyncio.Task`.

**Coroutine** — what calling an async function returns; inert until
awaited or spawned.

**The rim** — synchronous code around the coroutine world; it enters
with `run/1`.

## Specification

**GEP-0029-R001 (run):** `Task.run(coro)` runs a coroutine to
completion from synchronous code and returns its value —
`asyncio.run`, verbatim. It is the only Task function legal outside
an async body, and the entry point `main` stays synchronous
(GEP-0030-R001): a program's async portion hangs from one `run`.

**GEP-0029-R002 (async):** `Task.async(coro)` spawns a coroutine as a
task running concurrently with its caller and returns the handle —
`asyncio.ensure_future`. The join is the language's own `await t`,
bare and deadline-free. A task nobody awaits fails silently: await
what you need to see fail.

**GEP-0029-R003 (blocking):** `Task.blocking(fun)` returns a
coroutine that runs the zero-argument blocking function `fun` on a
worker thread — `asyncio.to_thread`, verbatim. Await it for the
value, or spawn it with `async/1` to overlap blocking work with
coroutines. This is the whole remaining role of threads in Task: a
bridge at the edge, not a world.

**GEP-0029-R004 (try_await):** `Task.try_await(task, timeout)` joins
with a deadline of `timeout` **milliseconds** (Elixir's unit) and
returns a verdict instead of raising: `{:ok, value}` when the task
finished, `{:error, :timeout}` when the deadline elapsed — the task
is then **cancelled**, asyncio's own `wait_for` semantics, honest
where threads had to shrug — and `{:error, error}` when it raised
(the exception as a value). The timeout is required: the no-deadline
join is the bare `await`, and a hidden default was this GEP's most
expensive lesson.

**GEP-0029-R005 (all / try_all):** `Task.all(tasks)` — awaited —
returns the values in input order; a crash re-raises at the join.
Its artifact is the sequential join `[await t for t in tasks]`: the
tasks already run concurrently, so joining in order costs nothing
and reads as exactly what it does. `Task.try_all(tasks, timeout)`
applies one group deadline of `timeout` milliseconds and returns one
R004 verdict per task, in order.

**GEP-0029-R006 (async_stream):** `Task.async_stream(xs, fun,
max_concurrency \\ 8)` — awaited — applies `fun` to each element,
running at most `max_concurrency` at once, and returns the results
in input order. `fun` MUST return an awaitable (call an async
function, or `blocking/1` for a blocking one); the bound is a
semaphore, visible in the artifact.

**GEP-0029-R007 (combinators):** After Gleam's promise module, four
non-joining combinators. `map`, `tap`, and `recover` return a **lazy
awaitable** — a coroutine composable anywhere one goes: await it,
spawn it with `async/1`, hand it to `run/1`. Laziness is what lets a
combinator chain be built on the rim and run later:

- `Task.map(task, fun)` — the awaitable of `fun(value)`; a crash
  propagates untransformed.
- `Task.tap(task, fun)` — runs `fun(value)` for its effect, passes
  the value through.
- `Task.recover(task, fun)` — the awaitable of `fun(error)` when
  `task` crashed, of the value when it did not (Gleam spells it
  `rescue`; `rescue` is a Gandora keyword).
- `Task.race(tasks)` — awaited — settles with the first task to
  settle, value or crash; the losers keep running.

Chaining (`promise.await`'s flatMap) stays absent: between two joins
Gandora has ordinary code.

**GEP-0029-R008 (shutdown):** `Task.shutdown(task)` requests
cancellation and returns whether the request took. Unlike a thread, a
running coroutine task really is interrupted — cancellation is one of
the reasons this world is the right one.

**GEP-0029-R009 (sleep / completed):** `Task.sleep(ms)` — awaited —
pauses the coroutine without blocking the loop. `Task.completed(value)`
is a coroutine already holding `value`, for APIs that must return an
awaitable uniformly.

**GEP-0029-R010 (zero runtime):** `Task` is an ordinary std module
written in Gandora — itself in the GEP-0030 syntax it rides on. Every
function is a thin, readable wrapper over `asyncio`; no scheduler, no
wrapper classes, no background threads, no module state.

**GEP-0029-R011 (determinism in tests):** Conformance tests MUST
prove concurrency structurally (e.g. an order both tasks must
observe), not by wall-clock thresholds that flake on loaded machines.

## Rationale

**One world.** The retired design maintained two Task universes —
thread futures joined by library calls, coroutines joined by
recompiled ones — plus a hidden loop to ferry between them. This
design has one universe with two doors: `run` from the rim,
`blocking` to the edge. Everything deleted was simulation cost:
`from_async` and its daemon-thread loop, `:infinity` (the bare
`await` is the no-deadline join), the emitted `_gan_try_await`
helper (now an ordinary std function), the unkillable-thread
footnotes.

**Verdicts over exceptions at deadlines.** A deadline is an expected
outcome, not an exceptional one; `{:error, :timeout}` composes with
`case` where `TimeoutError` handling breaks flow. The shape follows
Gleam's `try_await`; requiring the timeout argument follows the
measured failure of the old implicit 5000 (a model-facing surface
asserted "no deadline" over a hidden one).

**Sequential join as artifact.** `gather` was rejected for `all/1`
not for behavior but for reviewability: `[await t for t in tasks]`
is the loop a Python reviewer verifies at a glance, has identical
results-in-order semantics, and needs no splat plumbing through the
interop layer.

**Milliseconds** stay: Elixir muscle memory, one visible `/ 1000` in
the artifact.

## Backwards Compatibility

The thread-pool Task of revisions 1–4 existed only in an unreleased
working tree; this revision replaces it wholesale. `await/2`,
`await_many/2`, `try_await_many/2`, `start/1`, `from_async/1`, and
`yield` never shipped; their replacements are the language's `await`,
`all/1`, `try_all/2`, `async/1`, and nothing (a coroutine is already
a value; there is nothing to bridge).

## Security and Determinism

Tasks run arbitrary Gandora code on the caller's loop with the
caller's trust — no new boundary. `blocking/1` inherits
`to_thread`'s default executor; the module holds no state of its
own. R011 keeps the suite deterministic.

## Tooling and AI Usage

`Task` sits in the context pack's std list and the MCP corpus with
verified whole-module examples in the new shape: an async interior
(`Task.async` fan-out, `await Task.all` join, `Task.try_await` with a
visible deadline) under a sync rim whose `Task.run` doctest executes.
The MCP server itself is the reference consumer: its tool handlers
are async functions the SDK awaits natively, and its model call is
`await Task.try_await(Task.async(agent.run(text)), timeout)` — the
artifact a Python reviewer would have written by hand.

## Conformance

Tests MUST cover: `run` returning a coroutine's value from the rim;
value round-trip through `async`/`await`; structural concurrency
proof per R011; a crash re-raising at a bare join and arriving as
`{:error, e}` through `try_await`; `{:error, :timeout}` with the
task observably cancelled; `all` order preservation; `try_all`'s
group deadline; `async_stream` order and bound (the bound proven
structurally); each combinator including `race` settling on first
and `recover` absorbing a crash; `shutdown` cancelling; `sleep` and
`completed` round-tripping; and the doctests of the module itself
passing under `gan test`.

## Change History

- Revision 5, 2026-08-07: the asyncio pivot. Task becomes the
  library over the coroutine world under GEP-0030 rev 4's native
  syntax: `run`/`async`/`blocking` replace the thread pool,
  `from_async` and the background loop are deleted, `await/2` and
  `await_many/2` yield to the language's bare `await` and `all/1`,
  `try_await` requires its timeout and really cancels, `async_stream`
  takes awaitables under a semaphore. Threads remain only as
  `blocking/1`.
- Revision 4, 2026-08-07: R002 — `:infinity` waits without a deadline,
  in both joins.
- Revision 3, 2026-08-06: aligned with Gleam — `yield`/`yield_many`
  become `try_await`/`try_await_many` returning `{:ok, v}` /
  `{:error, :timeout}` / `{:error, e}`; the non-blocking combinators
  `map`, `tap`, `recover`, `race` after gleam/javascript/promise.
- Revision 2, 2026-08-06: R011 `from_async` — coroutines become
  ordinary tasks on a shared background loop; coroutine tasks really
  cancel.
- Revision 1, 2026-08-06: Initial version on `concurrent.futures`.
